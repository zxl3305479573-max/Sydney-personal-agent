本次子项范围：对 managed task 在执行工具准备与审批前增加授权资源预筛，保留审批后的事务复核；在辅助模型尚未纳入任务预算期间关闭 managed 自动模型审核，保留人工审批路径。验收是普通 Run 的原有审批行为不变，managed 不允许的工具不进入准备/审批，自动审核不会产生未计预算的模型请求；补定向测试并记录运行结果。

补充范围：Pi 的 `run_subagent` 等特殊工具可在 runtime 内直接执行，不经过普通工具门禁；managed 任务在工具暴露阶段仅提供已授权且已有门禁的工具，暂时关闭 helper、`ask_user` 和接管等直通入口，直到它们具备等价授权和预算检查。普通 Run 保留原工具列表。

控制链补充范围：native socket 请求接收现有 AbortSignal 并关闭在途连接；驱动已尝试在命令连接断开后清理进程组。此步骤只能提供尽力中断，不能证明脱离进程组的子进程已结束；跨进程任务控制信号及静止证明继续单独验收。

轮询子项（PA-005、PA-006、PA-014）：managed 运行时启动前及运行期间读取租户 Task 控制状态，出现 pause/cancel、任务切换、截止或读取失败时中断运行信号；普通 Run 不启用。轮询属于尽力传播，并发竞态、启动准备期间的动作和被中断的外部效果仍须保持未知，停止确认继续失败关闭。验收包括有效状态持续、状态变化与读取失败触发中断，以及退出后不再轮询。

本轮排队取消子项（PA-003、PA-005、PA-006、PA-010）：在任务行锁和版本检查下，仅对仍为 queued 的当前 managed Run 原子写入取消状态，使排队作业无法继续领取；与 Worker 抢占竞争时保留停止未确认状态，不推断后台工作已静止。交付包括并发条件的替身测试、计划和运维记录；真实 PostgreSQL 竞争与事件/清理联调仍需授权环境验收。

本轮结果投影子项（PA-003、PA-005、PA-006）：修复已完成 Run 无法进入用户结果确认、已核对效果被误判未决，以及历史截断时可能误报成功的问题；完成确认必须查询同任务全部 Run 的未决效果。补纯投影及替身检查，真实数据库和浏览器流程仍待验收。

本轮数据库边界子项（PA-003、PA-005、PA-006、PA-010）：按实际 Prisma 模型修正 effect 租户过滤，排除内部 checkpoint；结果投影依据当前 Run 指针，历史读取增加确定性排序和精确截断判断。交付包含边界测试、轻量验证与文档；真实 PostgreSQL、类型检查和浏览器回归仍为验收依赖。

队列事件子项（PA-003、PA-005）：排队 Run 的取消事件与状态同事务写入，提交后通知订阅者；派工重放也尝试以既有 replaceKey 唤醒，排队唤醒失败沿用修复器补偿。运行中控制仍不视为停止证明；需要真实数据库和队列并发验收。

重试限制：失败 Run 的终态不能证明后台静止；尚无服务端停止证据时，工作台禁用未静止或存在未知效果的重试。不能仅凭失败状态或客户端声明重新开放派工。

授权续期子项：派工已有历史 Run 时必须显式传入 `retry=true`；续期仅接受受管活动 Run，终态 Run 的旧授权不能延长。waiting 状态的实际租约和恢复语义仍待服务器联调。

原生文件准入子项（PA-004、PA-010、PA-012）：驱动对 list/read/write/export 再次校验 Run 身份、短期限及 fence；未携带或失效的执行授权直接拒绝。交付 Python 驱动定向测试和运维记录；Provider 与 Linux socket/账号权限的端到端验证依赖服务器，不能把该校验视为防范桌面同账号伪造或即时撤销的完整隔离。

启动准备控制子项（PA-005、PA-006、PA-014）：将 managed 控制轮询提前至取得 Run/电脑租约并创建 Attempt 后、执行器加载模型和连接等准备工作之前；在准备步骤之间检查停止信号，保持普通 Run 的控制流程。控制状态不允许或读取失败时不自动重排该 Attempt，不将停止视为静止证明；测试 watcher 和轻量语法，真实数据库、准备阶段竞态及已发出请求的中断待服务器验收。

工具分发中断子项（PA-005、PA-006、PA-010）：受管任务在工具解析、准备、审批门禁及授权检查返回后检查停止信号，减少停止后继续进入后续步骤的窗口；普通 Run 保持原行为。中断不撤销已发出的请求，也不证明效果或进程静止。新增定向测试但当前依赖不完整，尚未执行，需服务器环境回归。

桌面指针校验子项（PA-010、PA-012）：在发送指针移动前校验当前指针动作的类型和按钮，避免非法点击参数先移动鼠标；使用 Python 标准库替身离线验证，真实 X11 与多动作部分执行仍需 Linux 验收。

需求验收表子项（PA-001 至 PA-018）：建立首版需求逐项证据和缺口清单，以历史验证与当前审计为依据，不把离线接线或未运行的测试记为真实验收通过；阶段状态仍只在本计划维护。

创建幂等预算子项（PA-001、PA-004、PA-005）：同一创建 nonce 重放时逐项比较已保存预算，预算不一致则拒绝，防止把原任务误认为采用了新预算；新增数据库替身测试，真实 PostgreSQL 和当前不可用的 Vitest 仍需后续验证。

任务重试预算子项（PA-005、PA-006）：重试保留任务级模型、工具及 token 预留累计值和首次派工设定的总截止时间，过期任务不再派工；新增事务替身测试，真实数据库与完整 Vitest 环境仍待验收。历史运行已被重置的预算无法从当前状态可靠补回，不追溯推断。

## 1. 目标与范围

首版面向个人 PC 浏览器使用，完成“手动提出任务 → 授权 → Pi 执行 → 操作服务器桌面及文件 → 返回结果 → 查看记录”的闭环。

已确认方向：

- 以 Rakazo 固定版本为底座，保留现有 TypeScript 技术栈及 Pi 执行层。
- 后台、数据库与独立云电脑分布于两台 Linux 服务器；目标采用原生服务，不以 Docker 作为首版部署前提。
- 参考 DSH 的 Ticket / Assignment / Mandate 思路，分别表达任务、一次派工、授权范围；映射到现有 Run、审批、租约和存储能力，不先建设第二套调度器。
- 默认手动触发、一个主要执行任务；按具体资源协调并发，不在共享核心增加全局单任务锁。
- 一开始不加入主动接单、飞书事件、复杂多 Bot 群聊、递归子 Agent、支付、语音、移动端或插件市场。
- 首版保留显式记忆与历史查询要求，放在主执行闭环稳定后完成。

云电脑执行不默认授予 Agent root、sudo、后台密钥、数据库管理权限或控制服务器权限。需要的系统级操作另行定义范围与执行方式。

## 2026-11-04：数据库边界与排队事件修复

- 关联 PA-003、PA-005、PA-006、PA-010。依据 Prisma schema 修正 effect 查询：外层使用 spaceId，用户身份通过关联 Run 约束，并排除内部 runtime checkpoint。
- 任务投影使用 currentRunId 而非历史数组末项；历史读取按创建时间与 ID 排序，多读取一条判断截断，满额但未超限时不再误报不完整。
- 排队 Run 取消与 `run.cancelled` 事件在同一事务写入，事务提交后尽力通知；派工重放以 `keepExisting` 唤醒已有队列任务，避免覆盖已有退避。
- 验证：8 个 TS/TSX 文件语法转译无诊断；投影和历史上限内存替身 4 项检查通过。Vitest、完整类型检查、PostgreSQL 和队列联调未执行，见 V-014。
- 风险：Task、Run、Thread 的锁顺序与其他执行路径可能产生数据库死锁，需在真实 PostgreSQL 并发检验；已提交事件的订阅通知可能失败，依赖现有事件追赶机制。静止证据及暂停后恢复仍不可用。
- 重试审查：失败终态不能证明后台工作静止，因此没有放宽服务端门禁；派工事务额外检查活动 Run 和所有历史未决效果；工作台禁用未静止或未知效果的重试，并在当前 Run 缺失时隐藏初次派工入口。
- 授权生命周期：派工开始消费 `retry` 标志，已有 Run 必须显式重试；mandate 续期增加活动 Run 状态检查，终态授权拒绝延长。

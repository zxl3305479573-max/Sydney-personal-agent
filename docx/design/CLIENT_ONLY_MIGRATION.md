# 手机与桌面客户端迁移方案

关联需求：PA-021、PA-022、PA-023。阶段状态统一维护于 `docx/PLAN.md`。本方案为实施与验收依据，不表示客户端迁移或网页入口移除已经完成。

## 目标与现状

用户使用 iPhone 原生客户端及 Windows Electron 安装程序；两者连接现有后台，继续共享账号和数据。桌面安装包内置现有 Web 界面构建产物，以保持当前布局和功能，不要求用户通过浏览器访问。保留后台 API、认证、数据库、Worker、云电脑及必要代理；仅在依赖验证后移除面向浏览器的应用入口。

当前桌面远程模式加载服务端网页；打包资源只在受管理本机模式覆盖页面。手机端使用原生界面，但电脑画面使用 WebView，第三方授权可能需要浏览器及服务端回调。生产 Compose 实际位于云电脑；不可照历史 systemd 路径停服。桌面真实构建、安装、连接和本地渲染均未验收。

## 模块执行细目与交接

1. **C0 基线**：盘点 Web 路由、服务器代理和移动端调用；辨认生产部署、构建版本和现有数据备份。产出依赖清单及不可移除的 URL，所有线上信息实施前复核。
2. **C1 设计**：固定远程来源、session 与本地资源绑定方式；设计主窗口、弹窗和沙箱的权限边界、资源清单与缺失失败、启动探测、切服、OAuth、协议及 426 版本错误。独立审核威胁和兼容性，尚未解决的情况保持关闭。
3. **C2 实施**：先为请求分类、资源寻址和失败路径做定向验证，再接入桌面主进程和包内构建；测试 GET、HEAD、其他方法、编码、来源、请求头、跳转、WebSocket、Cookie 与资源缺失，最后执行打包端到端测试。与其他窗口共享的主进程文件必须先协调写集。
4. **C3 发布**：核查安装身份、路径与现有数据；确认可复现的 Windows 构建环境、构建标识及产物校验。客户端与服务兼容策略、可信更新源、签名和升级回滚分开交付，不能因打包成功就启用未验证更新。
5. **C4 手机**：建立登录、推送、深链、附件、屏幕代理和各授权回调清单；确保后台保留必要服务。针对 iOS 构建、签名、安装、登录、续签与更新各自记录结果和限制。
6. **C5 工作区**：依照 PA-022 先处理成员、账号及 Space 生命周期和创建并发门禁，再实现工作区 CRUD、Bot/群聊/会话服务端隔离与任务归属；逐步接入手机入口、桌面项目界面、云电脑只读及桌面授权。目录写入和执行分别经授权与审计验收后再开放。
7. **C6 双端回归**：使用独立受控测试账号和授权环境，验证账号隔离、断网重连、旧包兼容、删除及恢复、电脑接管和项目全链路；每个缺陷记录重现、修复及复验，不以单元测试代替真实设备结果。
8. **C7 收口**：先核对认证邮件链接、第三方回调、手机深链、屏幕与健康探测的实际流量和归属；制定部署、备份、恢复和分步撤回方案。先在受控环境证明无需网页应用入口，再按现行生产流程切换并检查两个客户端；保留必要回调和远程屏幕服务。

每项交接写明领取者、写集、需求编号、前置条件、完成证据和遗留问题。不存在的构建环境、审核结果或设备验证不得提前标记完成；现有用户数据和其他窗口改动需保留。

## 开发与审核规则

每个模块开始前在总计划记范围、依赖与验收；实现、定向验证、独立子代理审查、修复和复审循环，直到有效问题关闭。模块结果、未执行项和运行变化分别记录在开发、验证和运维文档。协调共享写集并保留其他窗口的未提交修改；不能因局部测试通过就宣称安装包或项目功能完成。

资源与 API 的安全边界、接口兼容以及更新策略必须经过实际验证；不把后台凭据、私钥或目录路径传给网页或写入记录。生产迁移先核对备份、迁移顺序及回滚，不能用生产用户数据作为隔离测试样本。本机不启动服务、数据库或做全仓构建；在获授权环境执行真实构建与集成验证。

## C0/C1 静态审查发现

2026-11-11 独立审核：网页 RPC、认证与 CSP 依赖当前服务器来源，SSO 回调、持久会话及桌面桥也按来源判断。优先研究继续使用受选服务器的 HTTPS 来源，并仅对可信安装包资源做覆盖，避免直接引入跨域 Cookie、WebAuthn 和回调问题；该方向尚非已验证实现。

现有覆盖在文件缺失时会转发服务器，而且处理器属于整个 session；直接为远程模式打开可能使远程页面或脚本获得主页面上下文，切换服务器、同 session 弹窗及 OAuth 回调也需单独处理。接入前须确定本地资源清单和受控文档路由，包内资源缺失时拒绝或显示受控错误；API、屏幕代理、设备 WebSocket 和明确的动态路径保留既有授权转发。不能通过放宽 CSP、统一伪造 Origin 或关闭 Web 安全来解决。

桌面本地界面更新依赖安装包版本，服务器要求更高客户端版本时单纯刷新无效。现有自动更新入口已关闭，打包配置仍有上游地址；在配置用户控制的发布源、签名与更新、回滚验收前不得将其当作可用更新链。最终方案必须验证 OAuth 弹窗不会继承超出自身权限的桌面桥、真实 Cookie 与 CSRF、屏幕和设备通道、跨服务切换，以及本地资源缺失和旧包提示。

后续静态审核确认：现有桌面启动除 `POST /rpc/health` 外还探测服务器首页；即使 API 健康，首页关闭仍会阻止打开。内置界面模式需要保留 RPC 契约检查，检查包内入口可读，并仅在该模式摆脱首页探测；旧远程和本机模式的行为及切服失败回滚须保留。RPC 健康不能证明登录、数据库或版本兼容。

2026-11-11 请求策略首轮审核：现有 `protocol.handle` 回调只给标准 Request，不能直接取得窗口及 frame 身份；OAuth 弹窗共享 session，不能凭同源或请求头断言请求属于主窗口。首版纯策略还遗漏真实 SPA 路由、根资源和回调，并存在路径前缀过宽问题。上述问题解决和真实 Electron 身份关联验证前，不能把试验策略接入主进程；主窗口桥权限、弹窗和 iframe 必须分别考虑。

2026-11-11 并行架构研究及独立复核：以主窗口 `webContents.debugger` 的 CDP 请求合成作为可研究候选，理论上比 session 级拦截更容易限定窗口，同时保留后台同源地址；这不是已选定或已验证的安全实现。复核指出 debugger 脱离后的竞态、主框架与子 target 区分、已存在的 Service Worker/缓存、同源弹窗对 opener 的访问、切服重叠与旧 default session 都须独立处理。不能仅凭 detach 事件或同源判断声称可靠阻断远程文档。

如继续评估，应在授权隔离环境使用锁定 Electron、临时数据和两个受控来源，覆盖主框架、iframe、worker、弹窗、旧缓存与 Service Worker；注入 attach、拦截、资源读取、detach 和切服失败，验证桥授权及时撤销且无远程 UI 回退，同时检查 API、Cookie、OAuth 和 WebSocket。该矩阵及桌面包尚未运行，生产模式保持原状。

## 手机端依赖核查

### 无域名直连后台（2026-11-11，进行中）

2026-11-13 手机启动屏障补充静态发现：`LayoutContent` 将服务器地址
和其他偏好加载放在同一个 `Promise.all` 中，并在该组任一任务失败后
吞掉异常；因此偏好加载先失败时，启动流程可以不等待仍在运行的
`loadApiBase` 就恢复通知并显示界面。此时 `currentApiBase()` 可能仍
使用包内默认值，已有会话也可能被读取。这是代码路径上的竞态风险，
尚未复现设备请求，也不能仅凭此判定线上实际泄露。

首步代码已改为等待所有启动任务结束，并通过定向测试确认偏好失败时
仍等待服务器任务；随后代码已对地址存储读取失败或无效地址拒绝启动，
并让已有错误边界提供重试。监控初始化在有效地址建立前不读取会话；
逻辑测试通过，但界面渲染及真实设备未验证。其他后台入口、凭据来源
绑定和完整迁移仍需审查，不能据此放行正式切换。

迁移实现须让服务器来源及凭据迁移成为独立的启动屏障：其他偏好失败
不能提前放行；来源或迁移无法可靠读取时须停止携带凭据的请求及通知
恢复，并提供可恢复的错误路径。还须覆盖异步请求和登录响应、存储
失败、进程中断及自定义地址；单纯改用 `Promise.allSettled` 不会
解决服务器加载自身失败或凭据来源绑定。修复与升级设备验证前保持
当前默认地址不变。

2026-11-13 手机升级路径静态核查：启动时 `loadApiBase` 优先读取
SecureStore 中保存的自定义地址，否则采用安装包中的默认地址；启动加载
不会调用手动切换时使用的 `clearCredentialsForEndpointChange`。请求头
生成又从独立存储读取会话令牌。因此，仅把新安装包的默认地址改成 IP，
不能假定所有已安装设备都会切换，也不能假定默认地址变化会清除旧令牌：
有自定义地址的设备继续使用保存的地址，没有自定义地址的设备可能向新
默认来源携带原会话。上述是源码路径分析，尚未在升级设备上实测。

发布前须分别处理全新安装、旧包使用默认地址升级、旧包保存了自定义
地址升级、用户手动切换和回退旧包；确认会话、所选空间、通知和未发送
消息的行为，以及旧地址与新 IP 确属同一受信后台。若不能安全证明旧
会话与新来源的关系，应要求重新登录，不能静默把凭据迁往其他服务器。
需先确定兼容旧版的迁移策略并在真实 iPhone 上演练；当前没有实现该
迁移，也没有更改默认地址。桌面端的独立 session 和升级行为需另验。

2026-11-13 未发送消息迁移补充：当前 `clearSessionToken()` 会触发
`invalidateSessionCaches()`，进而调用 `clearFailedSends()` 清理待发送
队列；发送队列按服务器、账号、Space 和缓存会话限定范围。因此不能
直接复用清除会话的流程作为默认地址迁移，以免未经用户操作丢失待发
消息，也不能仅修改队列的服务器地址就自动重发。迁移实现须先提供
可恢复的保留或显式处置路径，再分别验证会话失效、空间归属、附件、
队列重放及异常中断。以上为源码静态分析，尚未验证真实设备中的
队列持久状态；默认地址继续保持不变。

2026-11-13 队列读取保护：候选代码读取已保存队列时，如发现服务器、
账号或缓存会话不同的条目，则拒绝加载并保留索引与附件，避免将其
作为无主文件清理；模拟回到原范围后可读取附件。此修改不阻止显式
登出或会话替换所触发的队列清理，也不实现队列跨来源迁移或自动
恢复；真实设备、混合范围的恢复界面及异常中断仍待验证。

2026-11-13 来源绑定设计补充：只在无会话时保存当前默认来源的标记
不足以证明后续会话属于该来源；标记写入期间会话可能并发变化，
异常退出也可能留下先后顺序不明的记录。初步候选已撤回，未接入。
后续协议必须绑定具体会话并检查服务来源、会话代次、持久化失败及
崩溃恢复，同时覆盖密码、验证码、SSO、Passkey 和会话轮换路径；
不得将单一来源标记作为凭据可迁移的证明。

2026-11-13 来源保护候选：侧载包运行时在默认地址不是旧域名且没有
自定义地址时，检查现有按会话令牌绑定的已验证账号记录；已有会话
但来源缺失或不匹配时停止启动，无会话或记录匹配时继续。启动前的
API 请求、认证请求和会话头被阻止；检查本身不主动清除存储。代码
要求侧载构建显式设置 `EXPO_PUBLIC_SYDNEY_SIDELOAD=1`，当前工作流
已设置。显式自定义地址保持原有路径；旧域名若有明确属于其他
来源的已验证会话记录，也会停止启动。

已验证账号记录为可选数据：首次登录后尚未成功保存记录、存储出错或
旧包升级均可能被保守阻止；当前仅有通用重试界面，没有完成恢复或
迁移流程。旧域名回退路径、旧版二进制、密码轮换、并发和所有原生
网络调用尚未完整验收；不得据此放行真实升级或声称已保护所有设备。
真实构建环境中的公开变量注入、签名、钥匙串和 iPhone 也尚未验证。
旧域名仅在已验证记录确实不存在时保留旧会话兼容；读取失败、记录
损坏或令牌不匹配时阻止启动。缺失记录仍不能证明回退安全；已发布
的旧二进制也不具备本次保护。

2026-11-13 侧载测试身份门禁：当目标不是现有域名时，Expo 应用配置
拒绝使用侧载工作流默认标识 `xin.zxlup.sydney`，要求指定其他标识；
配置测试通过，工作流输入说明也已更新。此规则只保护已知默认标识，
无法识别用户可能使用过的其他正式标识；构建及安装前仍须核对真实
包标识、签名和钥匙串访问组。不同标识不自动证明数据隔离，不能用
测试包覆盖正式应用或据此将升级迁移标记完成。

桌面端静态代码按规范化 origin 派生持久会话分区；本机定向测试确认
示例域名与 IP、不同 IP 端口分区不同，公网 IP 拒绝明文 HTTP。
因此切换时应准备重新登录，并验证切回旧入口时的会话及连接配置；
这些测试未启动 Electron，也未验证真实证书、安装包或线上会话。

手机连接静态审查还发现：切换服务器与异步 RPC、登录返回并发时可能混用来源及会话；需统一绑定请求开始时的服务器、会话和空间，并防止旧登录响应覆盖新会话。认证与上传的重定向处理同样需要统一审查。React Native fetch 的备选实现可能忽略 `redirect` 选项，单靠请求参数或模拟测试不能证明拦截，更不能证明自定义头不会泄露；须明确实际构建使用的传输实现并在设备上验证。以上均未解决，不能将地址输入修订当作切服安全已完成。

2026-11-11 删除与切服恢复候选：必须分别表达“切服正在尝试”和“服务器或会话已实际替换”，不得在失败后直接回退代次，否则 A→B→A 可能让旧请求重新有效。服务端确认账号删除时，应先记录与原服务器及不可复用会话身份绑定的删除结果，再协调本地清理；失败的切服回滚不得恢复已删除账号的凭据，也不能清除已切换的新会话。删除 Space 的返回结果同样须绑定原会话和被删除的 Space，切服失败后只有仍属于原会话且当前选择未被更新时才能应用回退。通知恢复须绑定最终确定的服务器、会话及 Space。上述设计尚未实现；存储不可写或进程在确认结果持久化前退出时，还须明确恢复限制，不能声称内存状态提供跨重启保证。

推送清理边界：当前 schema 与迁移为用户关联的 `push_tokens` 设置删除级联，但旧服务或实际数据库迁移状态尚未核实；现有服务端删除前钩子仍会提前清理推送，后续删除失败也可能造成推送丢失。因此不能只移除手机客户端预注销就声称覆盖全部失败路径，须先核对兼容的服务版本及存储，再设计失败恢复和后续验证。

屏幕来源候选：服务端新增可选 `SCREEN_PROXY_PUBLIC_ORIGIN`，未设置时沿用 `WEB_ORIGIN`；配置后屏幕及终端能力 URL 使用指定 HTTPS 来源。移动端保留服务端返回的来源，拒绝 HTTPS API 会话中的明文屏幕地址，并对声明代理的路径做校验。Web/桌面仍会将画面地址改回页面来源，因此页面来源必须提供 `/novnc` 或先完成其他经过验证的分源方案。候选代码尚未部署，完整应用注入、真实代理、WebSocket、iPhone 及 Windows 测试均待完成。

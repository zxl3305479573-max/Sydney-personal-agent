## 现有基础

Rakazo 的 `apps/api/src/plugin-installs.ts` 已处理仓库插件预览摘要核对、技能和 MCP 连接器部件安装；`packages/core/src/plugin-catalog.ts` 是目录分类等逻辑，不能视为进程宿主。`packages/adapters/src/lazy-tool-catalog.ts` 提供连接器工具目录；工具审批与效果处理位于 `run-tool-gate.ts` 等现有路径。项目还有 MCP、连接器、Provider、Run 租约和审批基础，但实际授权覆盖、取消、静止证明和隔离仍需按现有审计与服务器验收核实。

现有插件安装与新宿主应先做映射和兼容性审计，不能假定已有插件均能运行于新协议，也不能把旧 MCP 子进程默认视为隔离。首版安全约束仍禁止动态加载未知工具和 Provider；新运行时在完成后续门禁及隔离验收前不得对外开放。

## 目标与非目标

目标是启停和升级插件时不重启核心，插件故障不终止核心或其他插件；受影响调用可以失败，外部副作用可能未知。默认关闭，明确启用、权限与运行位置。首个试点为受控只读工具，电脑 Provider 热切换、第三方市场和自动更新另行设计。

核心保留身份、审批、预算、租约、效果、审计；宿主仅提供生命周期和协议传输。所有调用经过既有门禁和网关，插件输出均为不可信数据。插件不可直接持有后台数据库或主密钥；凭据通过经审查的受控代理使用。独立进程只隔离故障，文件、网络、系统调用、进程、资源及凭据边界依赖实际 Linux 机制和实测，不承诺进程天然安全。

参考设计：[VS Code 扩展宿主](https://code.visualstudio.com/api/advanced-topics/extension-host)、[Backstage 扩展点](https://backstage.io/docs/backend-system/architecture/extension-points/)、[OpenClaw 插件架构](https://docs.openclaw.ai/plugins/architecture)、[Grafana 插件签名](https://grafana.com/developers/plugin-tools/publish-a-plugin/sign-a-plugin)。仅借鉴隔离、契约、注册和来源校验思想，不引入其运行时或依赖；签名不证明安全。

## 生命周期契约

离线试点已实现于 `packages/adapters/src/hot-plugin-pilot.ts`，只启动仓库内固定的 `hot-plugin-pilot-fixture.cjs`；通过 stdin/stdout 交换 JSON 行，协议版本为 1，只接收传入文本并返回标题，不访问文件。启动须握手成功，最多一个在途请求，限制请求和响应大小；停用先排空并等待子进程退出。样例测试模式仅用于触发崩溃、挂起或错误协议。此模块没有接入产品、安装流程、Agent 或生产网关；进程以当前账号运行，清空继承环境变量不构成文件、网络、进程或权限隔离。

离线决策状态为 `stopped`、`starting`、`ready`、`draining`、`stopping`、`failed`。只在 `ready` 允许发起新调用；健康握手之前不开放。停用先到 `draining`，仅调用计数为零时可请求停止；调用计数不是进程静止证明。只有宿主观察到进程退出后进入 `stopped`。失败或强制终止后仍须确认退出；未知外部效果单独记录，不因状态变化而推断成功、失败或可重试。

状态决策是无 I/O 纯函数，不保证原子性、身份或授权，不启动进程。宿主将来须在持久化事务和版本比较下执行决策；状态事件绑定插件 ID、实例代次、操作版本，拒绝旧进程回报。实际调用准入与停用需具备原子边界，跨 Worker 必须依赖共享权威存储或协调机制，不能依靠本机内存。进程在后台之外运行，其身份、认证和断连处理须单独设计。

升级将来采用新代先启动并验证、原子切换新调用、旧代排空、确认退出；旧代调用固定版本。权限扩大须重新授权；权限撤销立即阻止后续准入，已发出的请求可能不可撤回。迁移兼容与回滚需经插件级验证；未知副作用禁止自动重放。崩溃重启时以持久状态与进程身份核对，不能将失联当作进程退出。

## 分阶段交付与验收

1. 离线契约：定义生命周期决策与拒绝条件，测试启停、排空、失败和非法转换。无网络、进程、数据库和业务接线。
2. 受控宿主：定义版本化协议、受审查的只读样例、进程监控和资源限制；测试崩溃、超时、丢失连接及核心继续执行。此阶段不开放未知插件。
3. 安全接线：将能力注册、实际执行接入现有工具审批、Run 租约、预算、审计和副作用处理；增加事务并发、撤销、重复请求和重启恢复测试。
4. 热启停及升级：实现权威注册表、代次隔离、排空、回滚与 UI；测试跨 Worker 竞态和失败恢复，并于授权服务器验证。
5. 第三方开放：明确可信来源、包完整性、权限审批、Linux 实际隔离、配额、凭据及供应链策略；经过对抗测试和运维演练后再决定开放范围。

各阶段依赖上一阶段安全条件；进程宿主依赖取消和效果状态的真实语义，不能凭离线状态机宣布热插拔可用。生产升级、卸载及系统路径确定后同步运维手册；本轮没有新增配置或部署步骤。

## 工作区协同路线

| 模块 | 交付与依赖 | 验收重点 |
| --- | --- | --- |
| W0 隔离设计 | 对照现有 Space、会话、Bot、群聊、任务和权限，确定服务端归属与兼容策略；先于数据模型及界面实现 | 普通首页数据不迁移；所有服务端访问入口可校验归属；删除和运行中任务边界明确 |
| W1 工作区及目录绑定 | 实现工作区元数据、授权及安全移除；依赖 W0，并区分云电脑与本机位置 | 跨用户与跨工作区拒绝；移除不删除真实目录；断线和撤销明确反馈 |
| W2 文件夹内会话 | 工作区内创建、列出和访问 Bot、群聊及其历史；依赖 W0、W1 | 服务端强制隔离；群成员不得跨工作区；旧链接及搜索不能绕过 |
| W3 手机入口 | 原生首页底部玻璃入口及独立页面；依赖稳定的 W1、W2 接口 | 添加、切换、移除与创建入口可用，安全区及旧系统回退正常 |
| W4 桌面本机目录 | 桌面设备身份、系统目录选择、受限只读连接；依赖 W1 和经过审查的连接协议 | 设备离线及权限撤销准确；重解析点、目录替换和越界访问拒绝 |
| W5 Bot 项目操作 | 任务固定工作区与执行位置，按授权读取，逐步接入受限修改；依赖 W1、W2 及执行授权 | 切换不改变在运行任务归属，数据发送与变更可核对；未具备隔离条件时不开放任意命令 |
| W6 集成及独立审核 | 针对各模块的代码、安全、定向验证和构建进行独立审查，主窗口修复并复审 | 问题闭环、文档留痕；构建、安装、真实后台、手机及设备联调分别记录 |

这些模块是依赖顺序而非已派发实现。W0 确定接口前不并行修改共享数据模型；每项领取时在 `WORKSTREAMS.md` 登记实际执行者和不重叠写集。云电脑优先做已授权的只读接入，本机目录和后续写入、执行各自满足安全条件后再开放。Git 远端接入及跨设备同步继续按工作区方案分阶段实现。

## 目标与边界

以现有 Windows Electron 客户端为首个目标，主要布局对齐当前 Web 桌面工作台，复用 `apps/web`、共享组件、后台接口和既有认证。交付可追溯源码、Windows 桌面构建产物、审查与验证记录。构建成功、安装启动、真实后台联调和云电脑接管分别记录，不互相替代。

`apps/desktop` 已有启动、连接、窗口、打包等基础；远程实例会加载服务器页面。打包配置包含 Web 资源，但不能据此认定远程模式会使用内置资源。最终入口、资源加载及版本更新策略须先核对现有代码和真实环境，再决定是否修改。参照 `PC_CLIENT_INTEGRATION.md`，不擅自删除 Web 服务或新增一套客户端业务逻辑。

## 调度、审核与循环

1. 当前对话为总调度，维护唯一阶段状态、交付依赖和共享文档；实现前为每个模块记录实际领取者、写集和输入基线。
2. 优先使用用户要求的独立对话窗口实施，窗口完成后向本对话交接文件、验证和风险。当前会话未发现创建窗口工具，因此各模块为未派发；能力不可用时由当前窗口继续，不能虚报并行。
3. 用户于本次任务明确要求后期子代理审核；该要求覆盖此前不调用子代理的仓库约定。审核由独立子代理执行，重点检查回归、认证和授权、加载路径、打包及可验证性；主窗口复核发现并组织修复。
4. 每轮按“实现、定向验证、审核、修复、复审”推进，直到该轮没有未处理的有效问题；无法消除的外部依赖如实标注，不降低完成标准。
5. 不重装依赖、不启动本机 Docker、数据库或桌面服务、不做全工作区构建。本机仅做轻量验证；Windows 构建须先落实用户授权的适用构建环境。现有 `.github/workflows/release-desktop.yml` 是正式发布流程，手动触发也要求主分支上的版本标签，并会发布；不能直接用于本任务的非发布构建。不自动发布、提交或推送。
6. 共享工作区已有其他任务未提交修改；不覆盖、不带入无关产物。云构建若依赖提交或推送，需先确定不包含其他任务的可追溯源码以及用户允许的传递方式。

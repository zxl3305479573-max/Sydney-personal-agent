# 手机与 Windows 项目同步测评

日期：2026-11-21。关联 PA-022、PRJ-01、PRJ-02、P02-08。本文是验收清单，不代表测试已通过；实际证据写入 [验证记录](../VALIDATION.md)，整体状态以 [总计划](../PLAN.md#新目标手机与-windows-项目消息及执行位置协同pa-022prj-01prj-02) 为准。

## 目标

在同一账号和 Space 下，手机与 Windows 显示同一项目、Bot／群聊、消息、运行状态及成果。项目任务按创建时固定的设备和目录授权，在所绑定的 Windows 本机或专属云电脑执行；手机不直接执行桌面命令，也不把项目文件自动复制到后台或另一设备。设备离线、授权失效及任务结果未知必须准确显示。

## Windows 命令客体准备及安全检查

命令执行只在 Windows 客户端显式设置 `SYDNEY_PROJECT_WSL_DISTRIBUTION` 且所选发行版通过探测后可用。模型工具选择不代表 guest 已验证；实际运行前探测失败时，桌面端不请求本机命令确认，也不启动命令。当前 Docker Desktop 的内部发行版不是项目运行环境，不可作为该变量值。客户端不会自行创建发行版、安装依赖或改变 WSL 设置。

目标发行版必须是专门为项目命令准备的 WSL 2 客体：配置非 root 的 `sydney-project-runner` 账号、关闭 Windows 盘自动挂载与 WSL interop，安装受信任的 Bubblewrap、libseccomp 及只读 `/opt/sydney/project-command-runtime` 运行时。真实配置和安装方式需要先在隔离测试机验证并记录，当前不提供未经实测的安装命令。

安装候选后按顺序验证：

1. 未配置变量、变量格式非法、发行版不存在、发行版为 WSL 1、以 root 运行或客体组件缺失时，命令执行必须返回不可用，不请求 Windows 原生确认且不启动进程；绑定 Windows 目录时模型工具可能出现，但不能将其视为可执行能力。
2. 执行一条无输入的短命令及一条读取审批文件副本的命令；确认响应由固定设备、项目 Run 和 grant 返回，原目录摘要未改变。
3. 在命令中尝试读取 `/mnt/c`、Windows 用户目录、WSL 发行版外路径和未选项目文件；尝试网络连接、桌面互操作、`setsid`／`setpgid` 与启动后台子进程，均须被拒绝或限制在客体内。
4. 写入 `/workspace`、`/tmp` 后正常退出、超时、取消及断开桌面连接；确认没有文件写回项目目录，客体进程退出，未确认结果不自动重放。
5. 检查输出总量、UTF-8 输入、单文件／总输入上限、非法路径、重叠路径和边界超时；工具拒绝越界请求并保持任务状态可解释。

未完成目标发行版的以上实测前，Windows 项目命令仍为候选实现；本地现状和验证缺口以总计划及验证记录为准。

设计约定：工具选择只依据 Run 固定的 Windows 设备和目录授权，不将在线状态或历史 guest 能力作为可执行证明。项目审批后，设备在请求未发出时离线会保留原 Run 与审批并排队；连接恢复后重新读取当前绑定，并由 Windows 客户端在原生确认前执行隔离探测，命令启动前再由 guest 自检。探测失败时明确返回不可用，不启动命令。已派发后断线仍按结果未知处理，不自动重放。此离线候选接线不替代专属 guest 的真实隔离与双端验收。

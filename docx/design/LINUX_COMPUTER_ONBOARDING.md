# Linux 云电脑接入与切换

状态：方案草案，尚未实现。关联需求：PA-009、PA-010、PA-011、PA-012、PA-013、PA-015、PA-017、PA-018。

## 范围和现状

用户提供已有 Linux 云电脑的连接信息，由系统协助检测环境、准备必要组件并保存连接，之后可选择已接入的电脑。首期仅覆盖已有电脑，不创建云资源；系统发行版、架构和支持矩阵须以实际安装与测试结果确定。

当前 `native-linux` Provider 使用服务配置中的单个驱动 socket；已有驱动、SSH 转发和屏幕服务样例，但多目标配置、自动准备和安全切换尚未实现。现有服务样例不能直接视作任意 Linux 主机的安装器。

已新增独立的只读环境检查脚本 `infra/native-linux/inspect_environment.py`，报告系统、架构、发行版、用户主目录剩余空间、当前进程是否配置 `DISPLAY` 及部分程序是否在 PATH 中。它尚未接入远程连接或界面，程序存在不代表服务可用；`DISPLAY` 缺失也不能证明没有桌面。

## 用户流程

1. 输入连接名称、主机地址、SSH 端口和登录账号，选择专用 SSH 身份。首次连接展示主机密钥指纹，由用户通过可信渠道核对；密钥变更时阻止连接并提示重新核验。
2. 先只读检测系统发行版和架构、剩余空间、网络、桌面会话、所需程序及现有服务。展示可复用项、拟安装组件、来源、执行身份、预计影响和失败原因。不支持的环境明确退出，不执行猜测性的安装。
3. 对用户级准备按授权范围执行；涉及软件包管理、系统服务或 sudo 的步骤逐项说明并取得明确授权。下载使用固定版本和校验值，限制来源；不得执行未经校验的远程脚本。安装器须可重复运行，保留已有数据和服务。
4. 安装后检查驱动、授权连接、截图和画面通道，分别展示结果；检测失败不能显示为接入成功。保存连接时保护凭据，日志和任务记录不包含密码、私钥或令牌。
5. 在电脑列表中选择目标。后台先阻断旧会话新动作，处理或报告未结束操作，撤销旧租约并推进代次；确认新目标身份、授权与能力后才开放新操作。结果不明时保持不可操作，不能自动重放旧动作。

首次接入可能需要用户协助配置登录方式及确认权限，不能承诺仅凭地址就能完成安装。旧电脑断开不代表关机、停止计费或迁移文件、登录状态。

## 待实现交付

- 用户隔离的电脑连接资料与凭据管理：明确加密、密钥存放、修改、撤销与删除方式。
- SSH 主机身份校验、受限连接、准备任务进度与审计；复用现有驱动和 Provider，明确依赖下载及失败恢复。
- 每台电脑独立的驱动和屏幕通道，服务端持久化当前目标及代次；多进程和重启时不能各自选择不同目标。
- 接入、检查、切换和断开接口及工作台入口；隐藏或禁用尚未实现的操作。
- 安装、升级、卸载、回滚、数据路径与排障文档，实际命令须经目标环境验证。

上述连接管理会改变凭据、网络和权限边界；具体实现前需形成 ADR，并验证 API/Worker 与屏幕代理使用同一个已授权目标。

## 验收条件

- 两台受支持的 Linux 电脑分别接入，检测缺失组件、重复准备、失败重试和主机密钥变化；安装来源与完整性可核查。
- 切换期间运行中的任务、文件写入及人工画面均按会话隔离；旧代次请求不能到达新电脑，无法确定的动作不自动重放。
- 并发切换、服务重启、网络中断和安装中断后状态一致；错误清楚显示且不会伪装为成功。
- 凭据不进入普通日志或模型上下文；用户只能操作获授权的电脑，桌面不能获取后台密钥和数据库权限。
- 真实 Linux 上验证截图、输入、屏幕、撤销与恢复；记录测试环境、未覆盖项和回滚方法。

## 依赖与下一步

需要确认首批支持的 Linux 发行版及版本、SSH 登录方式、目标电脑是否已有桌面，以及后台能否连接目标 SSH 端口。先设计凭据存储与跨进程切换事务，再实现可离线验证的接入和切换组件；真实安装和双机验证须在用户授权的服务器上执行。

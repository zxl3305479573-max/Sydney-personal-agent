## 目标与范围

在用户明确选择并授权自己的 iPhone 后，让 Sydney 在可验证的设备会话中观察屏幕、
点击、滑动、输入及停止；优先研究手机 App 控制同一台 iPhone，Windows 方案作为备选，
不要求安装网页。
是否支持目标第三方应用、后台持续运行、iOS 26 和免费签名续期均需实测，不作预先承诺。

## 候选路径

普通 iOS 应用的系统沙盒不能为 Sydney 提供通用跨应用点击和读取能力；系统快捷指令
只能调用系统或其他应用暴露的动作，不能等同任意屏幕接管。苹果 FaceTime 的人工远程
控制和 Mac 的 iPhone 镜像属于系统功能，不能据此认定 Sydney 获得对应自动化接口。

### 手机本机控制：优先研究

2026-11-11 开源调研发现，现有项目使用开发者服务和运行器在手机上控制同一台
iPhone。此前只优先考虑 Windows 主机不符合用户期望，现予以纠正；这些项目属于
作者描述的开发者模式或实验性路径，不是普通 App 获得了公开的通用控制权限。

- [iphone-use-app](https://github.com/EliotAndres/iphone-use-app) 声称在 iOS 26+
  通过本机 VPN 回环与开发者服务截图和操作，配置完成后无需电脑持续连接。其文档
  要求初始 Mac 配对；免费账号使用外部 LocalDevVPN 并需周期续签。项目为 AGPL-3.0，
  不直接复制代码；必须评估许可、其依赖、分发与集成方式。
- [iCTRL](https://github.com/OpenMinis/iCTRL) 描述在设备上运行 XCUITest 运行器，
  提供本机调用接口，并可供手机上的 Agent 调用；文档描述免费账号侧载、开发者镜像
  和本机 VPN。实际签名、运行器能否与 Sydney 共存、进程生命周期、模型调用和用户
  当前 iOS 版本仍需验证；仓库说明当前为 Apache-2.0，1.32.0 以前的版本为 AGPL-3.0，
  具体版本和各依赖许可仍需在引入前核验。
- [TouchSynthesis](https://github.com/willfaust/TouchSynthesis) 描述 iOS 26 上的
  实验性本机事件合成，需要配对记录、开发者镜像和构建工具，采用非公开 XCTest
  能力；仓库许可、兼容性和分发条件尚待核实。

调研结论均来自项目自述，未经本项目独立设备验证。VPN 可能与现有 VPN 冲突，免费
签名、配对和设备状态可能需要维护；画面提交到云模型时会离开设备。禁止把测试
服务开放公网或把配对凭据写入仓库与日志。实施前需确定合法授权、版本兼容和
安全停止机制；不能把侧载测试机制视为 App Store 已认可的能力。

### Windows 连接：备选

研究 Windows 侧通过 Appium XCUITest 驱动连接已签名、已安装的 WebDriverAgent
（WDA）真机测试运行器：桌面端受控执行器连接用户手机，提供经授权的会话与操作接口；
后台和 Bot 仅使用能力接口，不直接访问设备或 WDA。该路线使用测试自动化机制，不是
普通手机 App 的原生全局控制权限。WDA 的签名、安装、启动、iOS 26 兼容性、Windows
连接与免费 Apple 账号限制均未验证；不要预设必须拥有 Mac，也不要承诺无需 Mac 就
能产出和续签所有需要的文件。设备屏幕采集与触控是不同能力，须分别验证。

## 建议架构

用户在 Sydney App 中发起任务并启动手机控制会话；现有后台负责任务和 Bot 调度，
通过经认证且可撤销的连接向手机上的执行桥发送有限动作。执行桥与本机控制运行器
通信，将必要的屏幕画面和操作结果按授权范围返回；运行器与桥不得直接暴露公网。
模型需要画面时，画面可能经后台发送给用户配置的模型服务，界面须说明这一点。
以上均为候选设计，具体进程、连接方向及屏幕采集方式以真机验证为准。

## 阶段、交付物与验收条件

1. **项目和许可核对**：固定候选版本与依赖，检查许可证、签名构建方式、开发者
   模式、配对、VPN、机型和系统版本。交付对照与失败记录；只有明确满足用户免费、
   Windows 环境的路径才能进入真机阶段，若初次需要 Mac 或付费服务须明确报告。
2. **授权真机最小演练**：确认 iPhone 已被识别、已信任且使用用户授权的签名材料，
   在独立测试 App 中依次验证启动、截图、点击、滑动、输入和停止；核对手机与
   控制运行器是否可在拔掉数据线后按预期工作。记录版本、操作结果及清理情况，
   不把项目自述当成通过。
3. **会话与权限设计**：为控制会话定义用户、设备、任务、操作范围、有效期、
   撤销、前台状态和超时；明确截图去向、敏感内容处理和不记录输入原文的审计。
   本机接口需验证调用方身份，退出、锁屏、失联和取消时均须验证停止行为。
   普通坐标点击无法可靠判断动作后果，发消息、支付和不可恢复删除遵循
   `docs/security.md` 的授权要求，不能声称仅靠坐标即可完全拦截。
4. **Sydney 执行桥**：以明确的接口隔离截图、点击、滑动、输入、状态和停止，
   适配已验证的本机运行器；不得让 Agent 核心直接依赖特定项目 SDK。先用测试
   替身验证状态和错误处理，再验证真机并覆盖超时后结果未知与禁止盲目重试。
5. **Bot 与界面接入**：在手机端提供控制入口、连接状态、可见的会话指示及停止
   操作；Bot 经后台能力接口调用受限执行桥。验证用户指定的测试流程，继续保留
   既有后台地址，不以模拟器或静态界面代替实际控制。
6. **真实 App、隐私和异常验收**：在用户授权的具体应用中逐项测试打开、观察、
   点击、滑动和输入；分别验证锁屏、切后台、断网、设备重启、VPN 冲突和签名过期。
   测试付款、发消息等外部动作前须有具体授权；验证码和个人数据不写入普通日志。
7. **交付与运维**：记录初装、配对、启动、断开、撤销、清理、签名续期和升级回退；
   明确免费条件及其限制。实际构建、安装、重启和续签实测通过后才能标记完成。

每一阶段都记录代码、验证结果、未完成事项和下一步；当前仓库约定不调用子代理，
由当前窗口检查，不把自查标为独立审查。Windows 远程连接路径仅在本机方案不可行
或用户需要跨设备控制时再评估。

### iCTRL 安装链和免费限制

项目描述的候选链路是：Windows 上使用 iLoader 安装 SideStore 并建立配对，手机
安装 LocalDevVPN；使用新版 SideStore 安装必需的 runner，再安装 iCTRL 主 App
或 StikDebug 中的一个以挂载开发者镜像。iCTRL 主 App 不是控制运行器本身，但该
无 Mac 挂载路径需要它或替代工具。首次挂载需联网获取设备相关签名票据，文档要求
Wi-Fi，重启后需重新挂载；设备需启用开发者模式。项目称旧版 SideStore 可能漏签
`.xctest` 而导致 runner 无法启动，具体可用版本尚未固定或验证。

配对文件不能混用：iCTRL 的无 Mac 挂载界面要求 **RemotePairing** 文件，而非
SideStore 常见的 lockdown 文件。[iLoader 固定源码 README](https://github.com/nab138/iLoader/blob/96ed06124d7a859692a5ec2864e1b47998d4904c/README.md)
称 Windows 需要 iTunes，并可管理两种配对文件；[idevice_pair 固定源码 README](https://github.com/jkcoxson/idevice_pair/blob/c8114c2bb88a80e2e17c0d9297b9915f09498ead/README.md)
描述 Windows 和 Remote pairing，要求 iOS 17.4+。它们是独立工具的说明，并非已在
Sydney 用户设备上成功生成或导入文件；iCTRL 在更早系统上的可用配对路径仍待验证。
不要将配对文件提交仓库、输出到日志或开放公网。

[Apple 免费开发账号官方说明](https://developer.apple.com/support/compare-memberships/)
列出：最多 10 个 App ID、最多 3 台设备，每项 7 天到期；每台设备最多安装 3 个
此类 App，开发描述文件自签发起 7 天到期。项目还称 SideStore 自身占一个安装位。
因此 SideStore + runner + iCTRL 主 App 已可能占满三个位置；若现有 Sydney 也使用
受该上限约束的免费签名，四者不能直接假定能共存。不同签名来源、扩展与 App ID 的
实际计数和当前设备状态未检查；App ID 限额也不能简单等同 App 数量。
续签需要实际运行与验证，不能承诺后台自动刷新或永久免费。

本机 `pymobiledevice3` 11.47.0 的源码提供镜像列表和 lookup；其注释区分
cryptex 安装与其他镜像安装方式，不能把单一查询未返回项目当作全部方式均未挂载。
代码的 iOS 27 自动挂载分支要求 RSD 隧道并可能下载或安装镜像，属于有副作用
操作，本轮没有调用。手机重新可访问后需先核对连接与既有信任，再选择只读查询，
只记录脱敏状态；未建立安全的 RSD 查询路径前不自动创建配对或运行自动挂载。

用户重新连接后，usbmux 检出 1 台设备；使用
[`iphone_image_readonly_probe.py`](../../scripts/iphone_image_readonly_probe.py)
禁用自动配对后连接，读取 iOS 27.0.1，并通过镜像服务检查 `Personalized`：
库返回 `false`。这是该接口的结果，不排除 cryptex 或其他挂载方式，也不证明
开发者镜像不可用。未下载、挂载或卸载镜像；RSD/cryptex 状态仍未查询。

随后使用 [`iphone_cryptex_readonly_probe.py`](../../scripts/iphone_cryptex_readonly_probe.py)
通过已信任的 USB 连接建立临时进程内 RSD 隧道，关闭自动配对和网络配对回退；
`cryptexd` 的已安装列表中没有发现开发者 DDI 标识。查询正常结束并关闭隧道，
只输出存在与否。此结果仅反映当时列表，不代表全部开发服务或其他镜像类型的
状态；没有安装镜像。按本任务顺序，解决证书和共存风险后再实施挂载验证。

### 测试包标识重写风险（2026-11-12）

再次将固定 runner IPA 读入内存并校验既有 SHA-256，解析其中主 `.app` 与内部
`.xctest` 的 `Info.plist`；原始两者 `CFBundleIdentifier` 相同。本机 iPASide
侧载源码默认生成团队后缀标识并将其传给 zsign。已查
[zsign 参考源码](https://github.com/zhlynn/zsign/blob/9299685bab7ef99827e06e5dfda93af747386590/src/bundle.cpp)
的 `ModifyPluginsBundleId` 仅选择 `.app` 和 `.appex`，未选择 `.xctest`。
据此推断，若安装版二进制与参考实现一致且主标识发生变化，保留目录仍可能留下
主应用与测试包标识不一致；参考源码另有遍历 `.xctest` 的签名逻辑，因此不能将
标识未改写直接等同“没有签名”。实际安装版二进制及输出包未验证，iOS 对该具体
组合的接受情况也未知。

后续无用户凭据的签名对照除了检查 `.xctest` 是否保留，还须解析签名前后的两个
标识、测试包签名及描述文件适配情况；比较重签后启动结果时不得覆盖 Sydney。
在这些验证前，关闭移除扩展选项仍不是可直接安装的充分条件。

### 上游签名流程对照（2026-11-12）

固定提交的 [iCTRL 签名脚本](https://github.com/OpenMinis/iCTRL/blob/c1e4268859ba858d1579f7b846a56cb40641b7f6/Scripts/sign-ipa.sh)
明确将 `.xctest` 的标识在签名前改为宿主 runner 标识，然后由内到外签名嵌套
代码与宿主，并运行严格签名验证。它筛选覆盖宿主标识、未过期且
`get-task-allow` 为真的开发描述文件，并要求签名身份的证书属于该描述文件；
它还设置宿主应用的 team、application identifier 和调试相关 entitlements。
这些是上游脚本的检查及签名流程，不是本项目已经验证的 iOS 接受规则全集。
固定公开 runner 的 XCTest 组件具有 CMS 槽但负载为空；不能对该组件进行
CMS 验签。使用合成自签名 CMS 的 OpenSSL 离线对照中，原内容通过而篡改
内容失败；该对照关闭证书链验证，不能证明 Apple 信任或真实安装可行。
脚本和 4 项解析器测试见 [`iphone_runner_cms_probe.py`](../../scripts/iphone_runner_cms_probe.py)。
进一步使用 [`iphone_synthetic_development_sign.py`](../../scripts/iphone_synthetic_development_sign.py)
对固定公开包预对齐测试标识并签名：自签名叶证书缺少颁发者链时失败，
改用合成 CA 链后，zsign 产生主应用及 XCTest CMS；OpenSSL 不验证信任链
时能验证两者签名，篡改 CodeDirectory 被拒绝，签名者与合成证书一致。
两项工具测试通过；该实验不证明 Apple 信任、全部嵌套代码、设备安装或
七天续签，且不能改用真实签名材料直接运行。

本机只读检查固定公开 runner，包内没有 `embedded.mobileprovision`；
因此必须在真实签名阶段提供适配的开发描述文件。先前预对齐 ad-hoc 实验的方向
与上游重写顺序一致，但没有验证开发描述文件、身份匹配、entitlements 或
嵌套签名的完整性。上游该脚本使用 Mac 的 Apple 签名工具；不能将它描述成已
验证的 Windows 免费签名方案，也不能据此推断现有 Sydney 证书可安全复用。

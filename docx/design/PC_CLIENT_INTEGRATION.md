# PC 客户端联调与迁移计划

状态：PC-01 代码已接线，正式域名和用户登录已获用户确认；Electron 端到端验收仍待完成。更新日期：2026-11-05。

关联需求：PA-009、PA-010、PA-011、PA-012、PA-013、PA-015、PA-016、PA-017、PA-018。

## 1. 目标

把现有 Electron 桌面端作为 Sydney 的主要 PC 入口，完成以下闭环：

1. 客户端可以连接后台 API，完成登录和会话恢复。
2. 用户可以查看 Bot、配置模型、进入聊天并收到模型回复。
3. 用户可以查看云电脑状态和真实桌面画面。
4. 云电脑连接失败、过期、断线和权限不足时，客户端显示可执行的恢复提示。
5. 后续移除独立 Web 服务时，PC 客户端仍能使用同一套聊天界面和 API。

本计划不新增第二套客户端业务逻辑。Electron 继续承载 `apps/web` 的界面；后期由云电脑上的 PC 后台承载渲染产物、PC 专用 BFF 和屏幕代理，认证、RPC、模型、Bot 和任务数据仍复用主后台 API 与共享契约。部署边界见 [ADR-0015](../../docs/adr/0015-pc-backend-on-cloud-computer.md)。

## 2. 当前基线

- `apps/desktop` 已存在，使用 Electron 45，产品显示名已为 Sydney。
- 客户端已经支持首次启动选择云端、本机实例或已有实例，并将已有实例地址保存到本地。
- 客户端已有服务探测、会话分区、外部链接隔离、更新和打包脚本。
- Electron 远程实例目前按“加载已有服务器的 Web 页面”工作；后台 Web 服务停止或移除后，不能直接假设 Electron 仍可打开界面。
- Web 登录、Bot、模型配置和聊天由 `apps/web` 提供，云电脑画面和原生启动租约仍依赖另一窗口处理中的修复。
- 后期 PC 客户端先连接云电脑 PC 后台，再由 PC 后台经受控链路访问主后台；不能把 SSH 回环转发地址当成最终客户端配置，也不能让客户端或云电脑桌面账号持有主后台 root、数据库或维护密钥。
- 打包部署可以通过 `SYDNEY_PC_BACKEND_URL` 指向云电脑 PC 后台；该变量只选择启动入口，不绕过 HTTPS、健康检查、登录或服务端授权。
- 正式入口为 `https://pc.zxlup.xin`；当前云端运行版本通过 `RAKAZO_ALLOWED_HOSTS` 设置 Host 白名单，仓库的 `PC_BACKEND_HOSTNAME` 接线尚未部署。用户已反馈正式域名登录测试完成，Electron 登录与其他功能仍需单独验收。
- `SYDNEY_PC_BACKEND_URL` 启动时先进行地址规范化与健康探测；不可达或响应不符时回到设置页。新增 Electron 端到端用例尚未运行，见 V-055。

## 3. 实施顺序

### PC-01：冻结客户端连接方式

先确认 PC 到云电脑 PC 后台的正式入口：

- 开发联调阶段允许使用本机 SSH 转发，地址仅绑定本机回环。
- 长期使用阶段使用受保护的 HTTPS 应用入口，或使用客户端可管理的受控隧道。
- 客户端只保存服务器 URL、用户会话和必要的本地界面设置，不保存服务器 root 密钥、数据库密码、模型明文密钥或云电脑维护密钥。
- `normalizeServerUrl`、健康探测、Cookie/Storage 分区和 WebSocket 同源规则保持有效。
- 部署环境可用 `SYDNEY_PC_BACKEND_URL` 预置入口；开发者仍可使用 `RAKAZO_WEB_URL` 或首次启动界面切换地址。

验收条件：客户端能够区分地址无效、服务不可达、服务不是 Sydney、证书失败和登录失败；错误提示不泄露凭据。

### PC-02：完成 Electron 基础功能联调

按以下顺序使用真实后台账号验证：

1. 首次启动选择“已有实例”并保存地址。
2. 登录、退出、重新启动后的会话恢复。
3. Bot 列表、主 Bot、空间和聊天历史加载。
4. 模型配置页读取、保存、校验失败和重新进入。
5. 发送普通聊天消息、流式回复、失败重试和网络中断后的恢复。
6. 附件、图片消息和聊天外观本地设置不破坏 Electron 存储分区。

验收条件：以上流程全部通过，Electron 与浏览器使用同一后台账号时数据一致；失败状态不会显示成已发送或已完成。

### PC-03：接入云电脑画面

依赖另一窗口完成手动启动租约和真实画面修复后，再在 Electron 中验收：

- 打开聊天中的云电脑入口，显示真实授权电脑画面。
- 显示电脑状态、分辨率、持久性和当前控制者。
- 画面加载失败时提供重试和返回聊天入口。
- 断线后重新连接不自动抢回人工控制权。
- 仅展示后端声明支持的动作；不支持的停止、销毁、接管能力不能显示为可用按钮。
- 画面权限与当前用户、空间和 Bot 绑定，不接受用户或模型任意指定的屏幕地址。

本阶段先做只读画面和状态验收。鼠标、键盘、终端、文件和人工接管必须分别记录结果，不因画面连接成功而整体标记为完成。

### PC-04：在云电脑部署 PC 后台并移除独立 Web 服务

用户后续移除 Web 服务时，采用以下目标结构：

- `apps/web` 保留为共享渲染源码和构建产物，不再作为必须长期运行的独立服务。
- 云电脑 PC 后台承载渲染产物、PC 专用 BFF、WebSocket/屏幕代理，并通过受控身份访问主后台。
- 主后台保留 API、Worker、数据库、任务控制、模型凭据和审计，不承载 PC 静态页面。
- 移动端继续直接使用 API，不依赖 Electron 或 Web 静态服务。
- 如果仍需浏览器测试入口，单独保留临时测试 Web 服务，并明确它不是生产入口。

实施前必须先核对当前 Electron 的 renderer fallback、同源认证、WebSocket、OAuth 回调、附件下载和屏幕 iframe 规则，并设计 PC 后台到主后台的认证转发；不能仅删除 `sydney-web` 服务。

验收条件：后台停止静态 Web 服务后，云电脑 PC 后台和打包 Electron 仍能登录、聊天、加载图片附件和连接云电脑；API 认证 Cookie、WebSocket、OAuth 和下载行为保持可用，主后台数据库和任务控制不迁移。

### PC-05：打包与恢复验收

- 先完成 Windows `pack:dir`，再决定是否生成安装包。
- 检查安装包启动、升级配置、桌面快捷方式和 Sydney 图标。
- 验证服务器地址切换、退出登录、清理本地会话和恢复默认设置。
- 记录 Electron 进程内存、启动时间和后台请求失败时的用户反馈。
- 形成一套可重复的开发联调和正式客户端验收命令，不把服务器 root SSH 命令放进客户端流程。

## 4. 当前不做的内容

- 不新建独立 PC 前端框架。
- 不把后台服务器的 root SSH 凭据、数据库访问或云电脑维护密钥下发到 PC。
- 不在客户端绕过 API 的用户认证、Run 租约、电脑租约或动作授权。
- 不因 Web 暂时用于测试就立即删除 `apps/web`；先完成 Electron 内置渲染和远程 API 验收。
- 不把本地 Electron 通过假数据启动视为真实后台联调完成。

## 5. 交付顺序与完成标准

| 子项 | 交付物 | 依赖 | 完成标准 |
| --- | --- | --- | --- |
| PC-01 | 连接方式和安全边界 | 后台入口可用 | URL 探测、证书、会话和错误分类通过 |
| PC-02 | 登录、Bot、模型、聊天联调记录 | PC-01 | 真实账号完成端到端流程 |
| PC-03 | 云电脑画面和状态验收 | 另一窗口的启动租约修复 | 真实授权画面可打开，断线和权限失败有明确结果 |
| PC-04 | 云电脑 PC 后台与主后台分离方案 | PC-02、PC-03 | 停止主后台静态 Web 服务后客户端核心流程仍可用 |
| PC-05 | Windows 打包和运维记录 | PC-04 | 安装、启动、切换服务器和回滚步骤可复现 |

当前先执行 PC-01 的代码和服务器入口核对，再执行 PC-02；PC-03 等待真实画面修复后接入。

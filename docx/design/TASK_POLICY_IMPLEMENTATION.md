# P2 纯策略接口与集成约束

日期：2026-11-03。关联需求：PA-001、PA-003 至 PA-006、PA-010。

状态：派工与授权纯策略已实现；后续已补 [状态投影与现有数据库只读适配](TASK_PROJECTION.md)，但未改 schema、API、Worker 或 Pi 执行入口。验证结论见 [验证记录](../VALIDATION.md)，架构取舍见 [ADR-0005](../../docs/adr/0005-task-policy-before-executor-integration.md)。

## 1. 派工判定

应用源码：`packages/core/src/task-assignment.ts`，入口 `decideTaskAssignment`。

输入是可信存储的一致快照：任务身份、Task 状态、请求 nonce、该任务全部 Run、历史完整标记、显式重试标记及 Run 数量上限。每条 Run 带身份、状态、原 nonce 和未核对副作用标记。兼容上游旧 Run 的空 nonce；新请求必须有非空 nonce。

| 结果 | 含义 | 调用方责任 |
| --- | --- | --- |
| `create` | 允许尝试新建 Run | 在现有事务中再次校验、保存并通过既有调度派发 |
| `reuse` | 相同请求已有 Run | 返回原引用和状态，不执行工具或将终止 Run 重排队 |
| `deny` | 未满足条件 | 展示原因，不自行改变任务状态或重试 |

拒绝条件包括空标识、非法状态/上限、历史不完整、跨用户/空间/Bot/线程/任务、重复历史、任务完成/取消、仍有活动 Run、未核对副作用、达到 Run 上限以及未显式请求重试。正在等待输入或接管的 Run 仍占用该任务的派工资格；不同任务不受全局锁限制。

本策略不产生 Attempt。Run 被现有 Worker 领取后仍由原租约机制创建 Attempt；同一 Run 的恢复、租约换代和运行内重试也不在本函数中实现。快照不完整时不能“先假定无副作用”；没有证据的操作按未核对处理。

## 2. 任务授权判定

应用源码：`packages/core/src/task-mandate.ts`，入口 `evaluateTaskMandate({ mandate, context, action, now, approvalDecision })`。

授权为可信服务提供的记录，绑定任务及一次 Run；同一任务新建 Run 后不得自动继承旧记录。精确条目必须在同一条里同时匹配工具、动作与资源，不能跨条目拼权限。有效期、撤销、现有审批、取消和人工接管均是必要条件。

`context` 必须显式包含运行状态、取消、租约有效及接管状态。只有 `runStatus = running`、未取消、租约有效、未接管且审批为 `allow` 时才继续范围检查；缺少布尔状态拒绝，不推定“没有取消”。时间使用非负安全整数毫秒，签发时刻包含、到期时刻排除；只要存在 `revokedAt` 字段即拒绝，包括未来或非法值，存储适配器须将“未撤销”规范化为不带该字段。

允许结果只表示调用时快照的范围判定。P3 必须补齐可信签发、服务端存储读取、撤销检查、租约 fence、资源规范化、动作前复核及审计。纯函数接受的 `source` 或布尔输入不是密码学证明，也不能直接取自网页、模型或客户端工具参数。

## 3. 结果未知与取消

网络超时、驱动进程消失、任务取消或 Worker 重启不说明操作没发生。工具适配器必须通过 ExternalEffect、幂等键或实际状态查询提供证据；未知时阻断新派工，不能把“重试已授权”等同于“旧副作用已核对”。

取消后策略不产生新动作，已有请求的真实结果仍需记录。数据库中状态取消不意味着操作系统已杀死进程，也不意味着外部请求撤回。原生桌面中的进程树取消和残留报告由 P4 实现验证。

## 4. 后续事务边界

1、按既有租户与线程/Bot 锁顺序加载 Task、Run 和待核对效果，不能另建全局锁。
2、判定后在同一事务中保存 Run 与幂等 nonce；数据库唯一约束决定并发请求的胜者。
3、重试保留旧 Run/Attempt，原子关联新执行，并写入不含敏感原文的事件。
4、工具执行前加载最新授权、取消、接管与租约 fence；不能把模型输出转成授权记录。
5、继续沿用已有审批和生产 host 保护，新增策略不得绕过。

以上是集成要求，尚未实现或通过 PostgreSQL 并发验收。本轮不声称端到端任务可以运行。

重复 nonce 的载荷一致性和归一化副作用状态也由后续服务端适配器保证；纯派工输入没有完整任务书或参数摘要，不能单凭它证明“相同 nonce 的内容未变化”。跨 Run 重试必须携带原已完成动作与产物，避免重做已确认的副作用，不能仅凭“没有未知结果”就重放全部任务。

# PC 界面与组件规划

状态：功能与交互规划；独立任务工作台已按用户要求从当前代码移除。更新日期：2026-11-04。

按 [ADR-0003](adr/0003-rakazo-fork-as-execution-base.md)，界面复用 Rakazo 原有 Web 界面。独立任务工作台、其侧栏入口与专用任务 API 已从当前代码移除。下述组件为产品目标，实时画面、接管和完整任务闭环仍待实现或验收。

关联需求：PA-001、PA-003、PA-006、PA-007、PA-008、PA-011 至 PA-018。

PC 对话的普通纯文本在请求等待期间显示本地发送中气泡；服务器事件通过请求标识与其去重，发送失败后撤回气泡并恢复未修改的草稿。附件、引用、提及及跨群发送仍使用原有流程；实际服务和网络验收待完成。

PC 群聊消息请求可与群列表并行，重开空间时可先显示同账号、同空间、同群的已缓存快照，再加载最新状态；历史消息跳转不使用该首屏缓存。首次无缓存仍依赖服务器快照，实际性能尚未测量。

PC 客户端启动页使用本地 SVG 路径遮罩逐步显露现有 Sydney 图标，加载工作并行执行；页面准备完成后交接，连接失败进入既有设置提示。系统减少动态效果时直接显示完整图标。Electron 实机、安装包和失败路径尚未验收，详情见验证记录。

聊天外观新增 PA-020：Web 和移动端均接入本地背景与消息气泡；Web 支持编辑和保存搭配，移动端支持本机图片与内置气泡预设。两端配置暂不跨设备同步，图片上传和真实存储仍按本地浏览器/设备保存；本轮 Web 颜色选择器按用户提供的 UIArc 参考结构重做，真实浏览器视觉验收尚未完成。详细范围及验证见 [聊天外观方案](../docx/design/CHAT_APPEARANCE.md)。

PC 单行表单使用共享输入样式；可复用字段支持标签、说明和错误提示关联，账号名称编辑已接入，视觉按用户提供的 UIArc Input 参考调整。聊天输入继续使用原有多行输入；真实浏览器视觉与键盘验收尚未完成。

PC 共享列表搜索和侧栏搜索按用户提供的 UIArc Search field 结构使用可见标签、搜索图标、固定清空槽、清空后恢复焦点；模型选择的命令式搜索保留组合框交互。其他独立搜索入口尚未统一，实际浏览器交互仍待验收。

PC 侧栏底部保留账号头像和名称，连接应用入口默认显示圆形图标，悬停或键盘聚焦时展开文字和已有应用图标；实际浏览器视觉和窄侧栏布局仍待验收。

PC 用量设置当前使用贡献日历式热力图；复核发现用户提供的是 UIArc Pro Cohort retention 三角图参考，当前实现尚不符合要求。接口最多返回 100 条记录及最近 12 周窗口，日期按 UTC 聚合，尚无 cohort 留存数据。

侧栏主 Bot 区使用现有 Bot 置顶状态，每个空间最多四个，可拖入、拖出、组内排序或通过右键菜单调整；置顶群聊仍在独立分组。旧数据若已有超过四个主 Bot，保留原状并阻止继续添加。实现和验证范围见总计划及验证记录；尚未完成服务器部署和浏览器验收。

## 1. 已确认方向与工作假设

- PC 优先，前端和共享契约使用 TypeScript。
- 暂按 PC 浏览器工作台设计，原生安装包形式待定，移动端不属于第一版。
- Grokbot 暂按 xAI 的 Grok Bot 理解，参考其功能组织与交互关系；若用户后续指定其他项目，调整参考来源。
- 输入框、搜索框和颜色选择器参考了 UIArc 的公开组件，热力图参考曾被误认；尚未完成真实浏览器截图比对，不能声称与用户参考完全一致。
- 保持自己的项目名称、视觉资产和文案；按产品需要选择组件范围。

Grok Bot 官方文档描述对话中的工具活动与结果，以及右侧电脑预览、打开桌面和人工接管的流程。[S1][S2] 本项目据此规划下面的工作台，不将未核实的布局细节当作事实。

## 2. 工作台布局

建议采用左侧导航、中间对话、右侧上下文面板的布局：

| 区域 | 内容 | 交互 |
| --- | --- | --- |
| 左侧导航 | 新建任务、会话与历史、电脑、记忆、设置 | 切换视图，保留执行任务的状态 |
| 中间主区 | 对话流、输入、步骤、授权和结果卡片 | 发起任务、补充指令、取消、查看结果 |
| 右侧面板 | 电脑预览、步骤详情、文件结果 | 标签切换、调整宽度、展开桌面 |
| 顶部状态 | 当前任务、电脑连接、控制者 | 查看详情、接管、停止 |

右侧面板可以收起或切换为较大桌面视图。PC 小窗口优先折叠侧栏，不能把关键的停止按钮挤出可见区域。

建议以 1440×900 为主要设计尺寸，1280×720 为最小验收窗口；这是项目目标，需在实现时实测。

## 4. 核心交互

### 发起任务

输入目标和附件，获得任务编号。任务与所选电脑绑定，展示步骤和真实结果。没有可用电脑时提示配置或连接，不让消息看起来已在执行。

### 观察与接管

点击电脑预览展开同一个桌面会话。默认观看，用户主动接管后控制服务撤销 Agent 输入租约；只有服务端确认接管成功，界面才接受人工输入。

归还控制后 Agent 重新观察桌面。断线重连不自动抢回控制权，不恢复已过期的租约。

### 切换电脑

显示当前 Provider、电脑、持久性和到期时间。存在运行中任务时，先提示处理该任务和未结束动作，再切换。切换完成后保留旧任务与旧电脑的关联。

“断开连接”“停止实例”“销毁电脑”使用不同按钮和说明，按能力展示，不合并成含义模糊的退出操作。

### 取消与急停

取消任务停止后续步骤。急停由控制侧阻断电脑操作与会话；有独立生命周期权限时可进一步停止实例。界面明确说明正在运行的外部请求和不可回滚操作。

没有独立停机能力时显示“停止 Agent 操作”，不能暗示已终止客体所有进程。整机停止入口按实际能力提供。

### 登录和敏感输入

需要人工登录时接管桌面，在必要阶段暂停向模型发送截图。不会把普通聊天输入框当作密码表单，也不承诺客体管理员无法读取客体内数据。

## 5. 前端边界

- 组件只使用应用 API、共享契约和已认证桌面会话，不直接导入供应商 SDK。
- 请求包含任务与电脑标识，服务端确认后才能改变控制权。
- 保留本地输入草稿，但不在浏览器持久化供应商密钥。
- 桌面连接地址不能是用户或模型任意指定的未校验地址。
- 模型输出、工具结果与文件预览按不可信内容渲染，禁止直接执行其中脚本。
- 键盘焦点进入桌面时才发送远程按键，保留明确的退出焦点方式。
- 所有主要操作支持键盘访问，状态变化有可读文字，不仅靠颜色。

## 6. 验收

- 在目标 PC 尺寸完成提交、查看进度、观看桌面、接管、归还和下载结果。
- 连接失败、授权不足、电脑过期及能力不支持均有明确提示和下一步入口。
- 同一桌面不出现 Agent 与人工同时输入。
- 切换 Provider 后界面不残留旧电脑的连接和控制状态。
- 所有展示为可用的主要按钮有真实行为；演示数据与真实运行状态明确区分。

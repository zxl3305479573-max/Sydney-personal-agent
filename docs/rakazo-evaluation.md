## 5. 迁移到服务器后的验收顺序

不再自动执行本机依赖安装、构建、数据库或 Docker 启动。取得目标 Linux 服务器的明确连接信息与操作范围后，再在服务器执行以下事项；不扫描本机寻找私人 SSH 密钥或推测服务器账号。

1. 在目标服务器验证代理、镜像网络和资源，完成 Linux 电脑镜像构建及独立测试数据库启动。
2. 执行上游 `pnpm dev`，核对 Web、API、Worker、Supervisor 健康状态，仅绑定本机地址。
3. 使用可控替身验证任务和工具路径，再接入用户选定的视觉模型。
4. 在一个 Bot 的专属测试电脑执行候选任务，核对画面、文件、结果和执行记录。
5. 测试审批、取消、断线、重启和人工接管；特别核对接管时终端和文件写入是否仍可继续。
6. 确认生产控制面隔离、真实场景、App、预算和备份策略，再开始 Sydney 界面和功能裁剪。

本机 Docker Desktop 试点的客体网络不提供已验收的控制面隔离。验证期间不挂载个人目录或控制服务密钥，不把容器内权限解释为生产隔离能力。

# 产品需求

状态：规划基线，第一版场景尚未冻结。更新日期：2026-11-03。

基于 [ADR-0003](adr/0003-rakazo-fork-as-execution-base.md) 的 Rakazo 与 Pi 底座，部署方向已由 [ADR-0008](adr/0008-separate-control-and-desktop-hosts.md) 调整为后台和独立 Linux 云电脑分机运行。上游已有功能仍须逐项验收，不能直接标为 Sydney 已实现。

## 1. 目标与用户

目标用户为项目所有者本人。产品帮助用户将明确的自然语言需求转为可观察的执行步骤，调用已授权工具完成任务，并在之后查找结果和用户主动保存的个人信息。

第一版优先回答三个问题：

- 用户能否通过一个入口完成常用任务？
- 用户能否知道助手做了什么、为何失败、是否产生了实际变更？
- 用户能否控制助手保存的数据和使用的权限？

## 2. 范围与假设

以下内容作为第一版建议范围，需在 M0 完成时确认：

| 项目 | 规划基线 |
| --- | --- |
| 使用方式 | 单用户，手动发起任务 |
| 开发语言 | Agent 使用 TypeScript；前后端共享契约也使用 TypeScript |
| 交互入口 | PC 优先，暂按浏览器工作台规划，原生安装包形式待定 |
| 运行位置 | 后台与云电脑分机原生 Linux；通过统一 Provider 和受控跨机连接 |
| 技术底座 | 基于 Rakazo 二次开发，保留 Pi；新增任务派工与授权策略，不增加平行运行时 |
| 并发方式 | 个人使用先以一个主要任务验收；按 Bot、电脑等具体资源协调，不新增全局锁 |
| 模型接入 | 复用既有模型接口；生产模型和数据发送范围待确定 |
| 工具范围 | 截图、鼠标键盘、文件和终端；默认仅桌面账号权限，不授予整机管理权 |
| 个人记忆 | 用户明确要求保存的信息，可查看、修改和删除 |
| 数据保存 | 任务和记忆由控制服务持久化；云电脑文件按 Provider 持久性能力管理 |
| 前端参考 | 参考 Grok Bot 的对话、电脑预览、接管与结果组织，详细范围见 frontend.md |

第一版不新增多用户账号体系、计费、后台定时执行、复杂多智能体协作和动态插件市场。终端执行限定在桌面账号及授权工作区，不开放后台账号、数据库或整机管理命令。

可插拔首先表示通过统一接口替换电脑来源，并不承诺运行中无损换机或将浏览器登录态自动迁移到其他供应商。

## 4. 需求与验收

P0 是第一版发布前必须满足的要求；P1 在核心执行闭环稳定后实现，也属于当前建议的第一版范围。若调整范围，应记录原因并同步路线图。

| 编号 | 优先级 | 需求 | 验收条件 |
| --- | --- | --- | --- |
| PA-001 | P0 | 发起任务 | 用户输入需求后生成唯一任务编号，可查询该任务 |
| PA-002 | P0 | 完成首个业务场景 | 使用任务书中的代表性输入，调用至少一个真实工具，返回可核对的结果 |
| PA-003 | P0 | 查询执行记录 | 可查看状态、步骤、工具结果摘要、起止时间和错误原因 |
| PA-004 | P0 | 控制工具权限 | 未授权资源无法访问；已有有效授权可复用；超出授权范围时请求确认 |
| PA-005 | P0 | 处理失败与中断 | 超时、模型失败、工具失败均有明确状态；重启后识别未完成任务，重试不重复造成副作用 |
| PA-006 | P0 | 取消任务 | 排队任务可直接取消；执行中任务停止安排后续步骤，并说明已完成的操作 |
| PA-007 | P1 | 管理个人记忆 | 用户可明确保存、查看、修改、删除记忆，修改后后续检索结果随之更新 |
| PA-008 | P1 | 查找历史结果 | 根据任务编号或简单关键词找到任务和结果，不要求语义搜索 |
| PA-009 | P0 | 配置与运行说明 | 新环境按文档完成配置和启动；缺少必要配置时得到清晰提示 |
| PA-010 | P0 | 保护个人数据 | 密钥和完整敏感内容不出现在普通日志中，数据存储路径和删除方式有明确说明 |
| PA-011 | P0 | 内嵌云电脑 | PC 工作台内查看真实桌面、连接状态和分辨率，支持断线重连 |
| PA-012 | P0 | 操作云电脑 | Agent 以桌面账号在授权范围截图、点击、输入、读写文件和运行终端；系统级安装另行授权，不默认 sudo/root |
| PA-013 | P0 | 管理电脑连接 | 首个 Provider 支持接入、检查状态、重连和断开；创建、启停、销毁等按能力声明提供 |
| PA-014 | P0 | 人工接管与急停 | 接管后 Agent 停止输入，归还后重新观察；控制侧阻断新动作并报告未结束进程，整机停机按独立能力提供 |
| PA-015 | P0 | 隔离控制与执行 | 云电脑桌面账号不能读取后台模型密钥、数据库文件或管理凭据，不能绕过授权调用后台和管理接口；隔离边界需实机验证 |
| PA-016 | P0 | 明确持久性和恢复能力 | 界面显示电脑是否临时、何时过期及文件保留方式；快照和恢复按能力声明验收 |
| PA-017 | P0 | 可插拔接入 | Agent 仅依赖统一接口；首个真实 Provider 和测试替身通过同一契约验证，未知能力明确不可用 |
| PA-018 | P0 | PC 工作台 | 在目标桌面分辨率完成对话、查看步骤、操作电脑、接管及查看结果，未实现入口不伪装可用 |
| PA-019 | 待设计 | 换肤插件系统 | 用户计划后续通过插件实现换肤；插件契约、权限边界和实现范围尚待决定 |
| PA-020 | P1 | 聊天外观设置 | Web 保留本地聊天背景管理，支持分别设置用户与助手文字颜色、预览、保存和恢复默认；换肤插件不在本轮实现 |

## 5. 非功能要求

- **可解释**：区分执行成功、执行失败和结果不确定，不能只凭模型生成的文字判定成功。
- **可维护**：模型、工具和存储能够通过接口替换，第一版不要求实现多个后端。
- **可观察**：每次模型调用和工具调用关联任务编号与步骤编号，不记录模型内部推理。
- **有界执行**：配置最大执行步数、单次调用超时和任务总时限；达到上限后停止并解释原因。
- **可恢复**：任务状态在进程重启后保留；不承诺自动恢复未确认的外部操作。
- **性能**：M0 定义首次可见反馈和端到端耗时的测量方法与目标值，模型和工具耗时分别记录。
- **成本**：记录模型供应商实际返回的用量；无法获取时标记未知，不估造费用。

新增需求时补充编号、优先级、使用场景和验收条件；影响模块边界、数据结构、权限或里程碑的变更同时更新相关文档。没有验收条件的想法先放入待决定事项。

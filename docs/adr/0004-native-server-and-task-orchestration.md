# ADR-0004：同机原生 Linux 与任务编排层

- 状态：历史决策；同机部署方向由 [ADR-0008](0008-separate-control-and-desktop-hosts.md) 替代，Rakazo/Pi 及任务编排决策保留
- 日期：2026-11-03
- 关联需求：PA-001 至 PA-018
- 前序决策：[ADR-0003](0003-rakazo-fork-as-execution-base.md)
- 执行计划：[docx/PLAN.md](../../docx/PLAN.md)

## 背景

用户在 Rakazo 评估后明确：后台和 Agent 操作的电脑就是同一台专属 Linux 服务器，目标为原生运行，不托管在 Docker 桌面中。本机资源不足，不再进行本机服务启动或重负载构建。

用户同时接受：保留 Rakazo 和 Pi，借鉴 DSH Superagent 的任务、派工与授权设计，先建立开发规则、过程记录和计划文档，再开始构建。

## 已确定方向

- 保留 Rakazo 固定版本和 TypeScript 技术栈，不整体引入第二套 Agent 运行时。
- Pi 继续负责模型与工具执行循环；上层任务身份、执行尝试和授权范围分别建模，优先复用 Run、审批、租约与存储。
- 部署目标改为同一台 Linux 服务器原生运行后台、数据库与 Agent 桌面。Docker 试点结论仅保留为历史。
- 原生 Linux 桌面需补适配，不能将当前 `desktop` Provider 的开发配置当作生产桌面能力，也不删除生产保护来绕过该缺口。
- 后台服务与 Agent 桌面按不同系统账号设计。默认不给 Agent 后台密钥、数据库管理或整机 root 权限。
- `docx/` 集中保存计划、开发过程、验证及运维记录，每完成一个部分同步文档；中文编号分点描述经用户要求执行的提交。

## 需要进一步落实

- P1 确定任务、执行与授权映射，不提前决定新增表名或建设独立数据库。
- P1、P4 确定本机通信、桌面协议、文件权限、进程取消、接管与密钥访问边界。
- P4 在授权的 Linux 服务器验证生产原生路径；同机账号分离不等同于完整 VM 隔离，不能承诺 Agent 获得整机 root 后仍保护后台。
- P5 前确认真实场景、视觉模型、数据发送范围及必要 App 授权；主动事件接单和复杂多 Agent 不属于当前首版默认范围。

## 影响

原 ADR-0003 的底座复用、许可证和独立代码副本决策保留；其中先验证 Docker 桌面的执行顺序由本决策替代。历史 Docker 部署建议与当前方向冲突时，以本决策为准。

早期需求中的“隔离控制与执行”在当前目标中体现为账号、权限、数据和接口边界，尚未完成安全验证；不以文档宣布已满足 PA-015。进一步实现须同步安全与架构文档及验收条件。

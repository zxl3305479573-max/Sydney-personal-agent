# ADR-0027：Windows 项目命令使用专属 WSL 2 客体隔离

- 状态：已接受（候选实现默认关闭，目标客体验收未完成）
- 日期：2026-11-21
- 关联需求：PA-022、PRJ-02、P02-08
- 替代或被替代记录：补充 [ADR-0022](0022-project-workspace-ownership.md) 的项目执行隔离要求

## 背景

手机项目任务需要在绑定的 Windows 电脑执行有限命令。把任意命令的工作目录设置到授权目录并不能限制 Windows 文件系统、网络、桌面会话或进程访问。普通 Windows 用户下的 Shell 也不能代表项目目录沙箱。项目文件内容只可在明确授权和文件协议下读取或写回。

## 候选方案

- 在 Windows 主机直接启动子进程：兼容性较好，但不能将 cwd 当作安全边界，因此不采用。
- 复用 Docker Desktop 内部发行版：该发行版由 Docker 管理，不是项目专属客体，身份、更新和宿主访问边界不受本功能控制，因此不采用。
- 在专用 WSL 2 发行版中用 Bubblewrap 与 libseccomp 启动每次临时沙箱：复用已安装 WSL 2 和 Linux 隔离工具，能限定客体文件视图、网络命名空间、系统调用及资源；需要专用发行版预配置、升级和实机负向验收，因此作为实现方向。
- 使用 Hyper-V VM 或独立容器：边界可进一步独立，但部署、生命周期和资源成本更高；目前不增加平台或依赖。

## 决策

采用专属 WSL 2 发行版作为运行客体，桌面端只向客体发送命令数组及用户明确选定的项目 UTF-8 文件副本。客体每次在新的临时 Bubblewrap 环境中启动进程，运行时只读，工作区与临时目录为限额 tmpfs；探测检查 WSL 2、非 root 专用账号、关闭 Windows 自动挂载及 interop、隔离工具与运行时可信度、禁网及进程逃逸条件。

每次调用仍需项目一次性审批与本机原生确认。任务固定设备、Run 和目录 grant；输入文件由桌面端现有目录句柄协议重新读取，不传递绝对路径。命令不能持久修改项目目录；需要持久改动时回到独立审批的项目文件工具。设备未知结果不得重放。

`SYDNEY_PROJECT_WSL_DISTRIBUTION` 必须显式指定发行版。工具是否出现在模型上下文中只取决于 Run 已固定的 Windows 设备与目录授权，不依赖设备当时在线；设备离线时可在项目审批后等待同一设备。Windows 客户端须在请求原生确认前检查发行版配置和隔离健康，命令启动前 guest 还须重新检查隔离条件。缺少配置、发行版不可用或任一隔离检查失败时不启动命令并明确返回不可用。客户端不自动安装 WSL、发行版或 guest 依赖，不把 Docker Desktop 发行版视作有效目标。

## 影响与限制

候选已接入契约、设备请求、桌面端 runner、项目文件读取、双重审批、工具选择及结果记录；runner 随 Windows 安装包打包。离线回归验证请求校验和模拟设备流，不证明特定 Windows 安装版、WSL guest 配置或内核隔离已通过实测。目标 guest 当前尚未准备，生产开关保持关闭。

运行过程中，用户提供的文件内容仍可能含有提示词或不可信数据；模型和命令都应按普通任务输入处理。此设计不授权 Git 推送、安装依赖、删除文件或其他持久副作用，也不提供本机 Windows Shell。

## 验证与重新评估

验收矩阵见 [手机与 Windows 项目同步测评](../../docx/design/PROJECT_DEVICE_SYNC_EVALUATION.md)。须验证离线时原 Run 排队且不重发、恢复后固定设备与 grant 不变、缺少 WSL 时命令不启动、主机挂载和互操作不可见、网络不可达、未选文件不可见、进程取消与超时、资源限制、临时写入丢弃、设备撤权与响应未知；并在目标 Windows 安装包和独立 guest 上重复。任一负向边界不能证明时继续关闭设备命令功能并重新评估 Hyper-V VM 等更强边界。

# ADR-0001：本地优先与模块化单体

- 状态：已替代，保留早期规划背景
- 日期：2026-11-03
- 关联需求：PA-001、PA-003、PA-005、PA-009、PA-010
- 替代记录：[ADR-0002](0002-pluggable-cloud-computer.md)

本文的本地优先方向已由用户提出的云电脑需求调整；控制侧保持模块化单体的思路保留。下文为历史提议，不作为当前实施依据。

## 背景

项目从空仓库起步，目标是个人使用的智能助手。首个业务场景和技术栈尚未确定，需要先提供易于实现、调试和维护的架构起点。

第一版需要串联任务执行、工具权限和数据记录，但目前没有多用户或分布式运行需求。

## 候选方案

| 方案 | 收益 | 成本 |
| --- | --- | --- |
| 本地优先的模块化单体 | 部署环节少，便于调试和控制个人数据 | 需要主动保持模块边界，跨设备能力有限 |
| 云端优先的单体 | 跨设备访问较方便 | 增加账号、托管、网络暴露和隐私管理工作 |
| 多服务或多智能体系统 | 可分别部署和扩展职责 | 增加通信、状态一致性、恢复和运维复杂度 |

## 提议

第一版采用本地优先的模块化单体，任务和记忆默认在本地保存，模型、工具、存储以内部接口隔离。

本提议不指定语言、框架、数据库、交互入口或模型厂商，也不承诺离线推理。具体选型分别记录决策依据。

## 影响与限制

- 优先完成一个可验证的任务闭环。
- 权限检查和任务记录仍需完整实现，不能因为本地运行而省略。
- 初期只需一个应用进程，但应避免界面直接访问工具或存储。
- 如后续需要远程访问或后台执行，重新评估身份认证、运行隔离和部署方案。

## 接受条件

M0 确认首个场景可在该架构下实现，并明确本地数据目录、模型数据发送边界和运行方式后，将状态更新为“已接受”。

若实际场景要求其他架构，记录替代决策并将本文标记为“已替代”，保留历史原因。

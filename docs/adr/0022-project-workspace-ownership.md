# ADR-0022：项目工作区的成员归属与元数据隔离

状态：模型与迁移草案已添加，数据库及运行验收待完成。需求：PA-022。

## 决策

文件夹工作区归属于一个 Space 中的一个成员；元数据以不可透明的独立标识区分，路径和显示名不用于证明身份。普通首页历史数据不迁移到新工作区。`project_workspaces` 通过 `(spaceId, userId)` 复合外键引用成员，行级策略同时限定两项，系统任务沿用现有受控 RLS bypass。运行角色需满足现有最低权限要求，策略不替代应用认证及工作区授权。

先增加空的元数据表与生命周期标记，不开放目录绑定或项目会话写入；所有隔离路径和旧版本兼容完成前不能启用工作区。外键使用限制删除：成员或 Space 被移除前，应用必须先停止工作区访问、处理任务和授权，再清理元数据；不得依赖数据库级联跳过这些步骤。

## 实施与限制

2026-11-13 外部操作续项：CloudAgent 与 Purchase 保存可空项目快照，
系统 worker 按作业行恢复项目，即使聊天及 Bot 已删除也不依赖父记录
反推；Cloud Agent 增加原先缺失的账号/Space/system RLS，并与 Purchase
共同受到项目限制策略。两个外部表保留项目非空禁写 CHECK 和范围索引，
不加元数据 FK，以保留既有外部操作可在聊天删除后完成取消/对账的要求。

启动新操作仍从实际 Thread/Bot/群成员解析归属；重放验证来源，支付
远端响应后检查原聊天 generation，避免把响应发进后来恢复的对话。外部
provider 已发生的作用不能靠数据库回滚；删除/切换时须记账、停止新动作、
按快照继续对账，只在原关系有效时创建后续 Run。项目删除、Space/账号
删除与外部作业之间的门禁/保留/终止协议仍未实现；既有 Purchase→Space
cascade 保持不变，不能声称这层生命周期已完整隔离。

2026-11-13 父子一致性草案：新增
`20261119150000_project_conversation_consistency`，将项目及五类核心
会话对象的身份、账号、Space 和项目固定，线程/Task/Run 的目标固定；
外部会话身份与 Bot 也不可改绑。新写入核对父 Bot、群成员、线程父对象、
Task 的会话关系和 Run 与 Task 的归属。允许同值身份更新，普通名称/
状态及父 Bot 的同范围关联可更新，不通过改字段迁移历史对象。

采用调用者权限的触发器，使用空值等价比较：首页和首页相同，首页与
任何项目不同。现有项目复合外键只核对元数据归属，空值的外键语义不能
代替上述父子关系检查；因此不只依赖新增可空外键。触发器不使用系统
提权，RLS bypass 仍受约束。身份固定后不允许父对象并发改归属，删除
继续由既有外键处理；群成员移除、项目撤销及外部副作用仍需独立门禁。

迁移不验证全部既有关系，未来解除禁写前须完成历史审计、兼容、级联及
并发验收。新增 PostgreSQL 测试草案只使用合成首页数据，不移除项目
CHECK 造数据；SQL、测试和实际部署均未运行验证，不能认定完整隔离。

2026-11-13 核心执行归属续项：新 Task 的项目从存储的 Thread、Bot 及
群成员/外部会话关系解析，不能由客户端字段代替；新 Run 从刚保存
Task 继承。系统继续执行也使用目标存储关系，租户调用另需匹配当前
项目，关系不存在或账号/Space 不一致时拒绝。解析在原创建事务内
执行，但它本身不提供项目归属不可变或完整生命周期锁；前者的数据库
草案见上述续项，后者仍待实现，均未获得真实数据库验收。
后台 Run/Thread 作业从系统所有者读取中恢复项目，非会话作业显式
清空，避免继承调度调用方的项目。随后接入其他运行时 Task/Run
创建入口，静态发现的 22 处组合均传递归属；定时和技能作业从已核对
账号/Space 的 Bot 恢复项目。代码与测试草案未运行验证，禁写 CHECK
不解除，不能由创建入口数量推断全部资源已经隔离。

跨 Space Bot 通信守卫在既有双方 Bot 锁下比较项目：普通首页与项目、
不同项目均拒绝，同一项目必须相同账号和 Space；普通首页跨 Space
规则保留。缺失归属不能当作首页。本守卫不替代来源 Run 授权、项目
存活/撤销、其他共享路径和父子不可变约束。云代理和支付作业仍需
独立持久项目归属以支持父对象删除后的外部清理，不能只依赖 Bot
关联查找。辅助 RLS、工具、资源、生命周期与真实隔离验收仍待完成。

2026-11-13 项目上下文与核心 RLS 草案：在租户上下文中携带可选项目，
相同租户的嵌套操作继承；显式空值为首页，换租户不继承。SQL 连接每次
借出时同步或清空选择，短事务也设置该值；选择应在事务开始前完成。
通过元数据可见性检查的服务端入口可进入项目范围，尚不接受客户端
参数。核心五表使用限制性策略叠加已有租户/系统策略，群聊与成员
接入 RLS，事件经所属 Thread 检查。现有系统 bypass 延用原机制，
缺少项目设置的旧服务只读首页，不把缺少选择解释为所有项目。

Bot/群聊仓储及托管任务使用当前范围，创建的 Thread 和托管 Run 继承
父对象归属；托管任务 nonce 在项目间独立，首页算法保留。元数据查询
检查不锁定整个后续操作，RLS 需继续逐次校验项目与成员存活；它也不
替代父子对象一致性、任务授权、流式上下文、后台执行或生命周期门禁。
普通消息、外部交接、附件、记忆等尚未完整适配，五表禁写 CHECK 继续
保留。代码、SQL 及测试草案均未执行验证，不构成部署或隔离验收。

2026-11-13 会话归属基础草案：Bot、ChatGroup、Thread、Task、Run 增加
可空项目归属，以 `(projectWorkspaceId, spaceId, userId)` 复合外键指向
项目元数据。空值仅代表普通首页，不是所有项目。现阶段 SQL CHECK
强制五张表的项目归属为空，禁止在旧读写链路尚未适配时产生项目会话；
所有者复合外键不能替代父子会话、群成员或运行之间的归属一致性校验。
后续完整隔离验收通过后才能通过独立迁移解除约束，不能以租户参数、
环境开关或 RLS bypass 绕过。模型与 SQL 均未运行验证，迁移尚未应用。

2026-11-13 只读接口草案：允许将已有元数据通过认证 RPC 列表和详情
返回，读取同时限定用户、Space、有效成员及未删除状态，不暴露路径。
这不开放工作区创建、目录访问或项目会话写入，不变更以下生命周期
门禁；新增接口和桌面页面均尚未运行验证。数据库迁移和旧部署的兼容
必须在上线前核验，失败不能转为读取普通首页。

Prisma 模型和迁移已编写，但尚未在 PostgreSQL 上应用。当前成员、Space 和账号删除流程尚未接入上述清理，**工作区创建保持关闭**；在存在工作区数据时直接删除成员、Space 或账号会被外键阻止，已有外部清理可能先发生。启用前必须完成删除流程、并发与失败恢复测试。

Space 及账号删除现已增加外部副作用前的工作区检查，且检查系统 bypass 是否生效；它们仍不是工作区清理流程。数据库或 bypass 不可用时拒绝删除。账号预检与实际删除之间尚无持久门禁；已被旧 worker 领取且同时存在工作区的 Space 保留 claim，须先核查在途工作再处理。新代码必须在元数据迁移完成后部署，避免缺表造成所有相关删除失败。

运行角色必须不是表所有者或超级用户且不具备 `BYPASSRLS`；须核实 `app_rls_bypass()` 依赖的密钥和延迟迁移已正确配置。应在授权服务器验证同 Space 不同用户、不同 Space、无上下文、写入伪造归属、系统访问、成员删除和连接池复用。元数据 RLS 成功不代表聊天、Bot、任务、附件或文件访问已隔离。

迁移本身不含目录路径或文件内容；未来绑定方案须单独设计授权、撤销及数据保留。回滚到旧版前先停止工作区读写并处理任务、备份关联数据，禁止让旧版本忽略工作区归属继续操作。

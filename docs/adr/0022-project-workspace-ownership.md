# ADR-0022：项目工作区的成员归属与元数据隔离

状态：模型与迁移草案已添加，数据库及运行验收待完成。需求：PA-022。

## 决策

文件夹工作区归属于一个 Space 中的一个成员；元数据以不可透明的独立标识区分，路径和显示名不用于证明身份。普通首页历史数据不迁移到新工作区。`project_workspaces` 通过 `(spaceId, userId)` 复合外键引用成员，行级策略同时限定两项，系统任务沿用现有受控 RLS bypass。运行角色需满足现有最低权限要求，策略不替代应用认证及工作区授权。

先增加空的元数据表与生命周期标记，不创建对外 API 或目录绑定，不改写 Bot、群聊、线程或任务；所有隔离路径和旧版本兼容完成前不能启用工作区。外键使用限制删除：成员或 Space 被移除前，应用必须先停止工作区访问、处理任务和授权，再清理元数据；不得依赖数据库级联跳过这些步骤。

## 实施与限制

Prisma 模型和迁移已编写，但尚未在 PostgreSQL 上应用。当前成员、Space 和账号删除流程尚未接入上述清理，**工作区创建保持关闭**；在存在工作区数据时直接删除成员、Space 或账号会被外键阻止，已有外部清理可能先发生。启用前必须完成删除流程、并发与失败恢复测试。

Space 及账号删除现已增加外部副作用前的工作区检查，且检查系统 bypass 是否生效；它们仍不是工作区清理流程。数据库或 bypass 不可用时拒绝删除。账号预检与实际删除之间尚无持久门禁；已被旧 worker 领取且同时存在工作区的 Space 保留 claim，须先核查在途工作再处理。新代码必须在元数据迁移完成后部署，避免缺表造成所有相关删除失败。

运行角色必须不是表所有者或超级用户且不具备 `BYPASSRLS`；须核实 `app_rls_bypass()` 依赖的密钥和延迟迁移已正确配置。应在授权服务器验证同 Space 不同用户、不同 Space、无上下文、写入伪造归属、系统访问、成员删除和连接池复用。元数据 RLS 成功不代表聊天、Bot、任务、附件或文件访问已隔离。

迁移本身不含目录路径或文件内容；未来绑定方案须单独设计授权、撤销及数据保留。回滚到旧版前先停止工作区读写并处理任务、备份关联数据，禁止让旧版本忽略工作区归属继续操作。

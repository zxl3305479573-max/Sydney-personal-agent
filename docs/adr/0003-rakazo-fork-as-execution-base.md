# ADR-0003：以 Rakazo Fork 作为执行底座

- 状态：决策已接受，源码导入完成；本机运行试点已停止，运行验证待迁移到服务器
- 日期：2026-11-03
- 关联需求：PA-001 至 PA-018
- 上游仓库：https://github.com/elie222/rakazo
- 评估基线：aebca9dcfd0cf734484ce41e3c5ad9521551659d
- 许可证：Apache License 2.0

## 背景

本项目最初尚无应用代码。Rakazo 已有 TypeScript 控制服务、Pi Agent 运行时、Linux 电脑 Provider、工具审批、任务存储及连接器实现，且主要模块边界与本项目已规划方向一致。

从零实现这些基础能力会重复承担 Agent 执行循环、电脑生命周期、任务恢复、授权和 Provider 兼容性工作。直接照搬所有产品功能则会带入移动端、多用户、语音、群聊、支付等当前不需要的范围。

## 决策

- 将 Rakazo 固定版本源码直接放在本项目仓库根目录，保留上游 Git 历史及 `upstream` 远端；应用源码和项目文档在同一工作区维护，不另设代码子目录，不创建远端仓库或推送。
- 把固定提交的可运行性和单用户 Linux 电脑任务闭环作为第一阶段验收，暂不开发产品定制功能。
- 优先复用 Pi 运行时、任务执行、Computer/Sandbox Provider、Linux 桌面、授权审批、存储和连接器底层。
- 后续按需求裁剪或重做界面、身份与单用户配置、权限策略及电脑隔离；不把上游 Team Computer 的目录划分误作安全隔离。
- 暂缓多 Agent、群聊、移动端、语音、支付、定时任务和插件市场；只有首个真实场景证明必要时才加入。
- 本机资源不足时只做文档和代码编辑。按用户最新要求，停止本机 Docker、数据库和桌面构建；后续运行验证转到单独服务器，不自动恢复本机重负载任务。
- 保留 Apache-2.0 许可、上游版权及 NOTICE，清楚记录本地修改和上游基线；改写或删除上游组件时检查对应许可证义务。

## 试点验收

1. 固定提交可按上游说明安装和启动，配置与本地个人数据不进入版本控制。
2. 单用户可使用 Linux 电脑 Provider 完成一次手动任务并查阅真实执行记录。
3. 审批、任务取消、异常恢复及 Provider 行为至少有一条实际验证路径。
4. 核实控制服务、Worker、数据库、电脑运行时和桌面画面的网络与权限边界。
5. 记录尚未满足 PA-001 至 PA-018 的行为、已知限制、依赖及实际资源占用。

技术方向已同步至受影响文档；试点通过后再按实际差距细化产品需求、系统架构、安全设计及路线图，把“采用 Rakazo 代码”与“满足 Sydney 需求”分别验收。当前验证证据见 [试点记录](../rakazo-evaluation.md)。

## 取舍与风险

- 收益：先复用有实现和测试的执行基础设施，缩短首个真实任务的验证路径。
- 成本：上游工程规模较大，需维护 Fork、理解既有约定并持续处理上游更新。
- 风险：上游功能、安全假设或依赖版本未必满足本项目约束；必须逐项审查，不把上游行为视作本项目安全验收证据。
- 回退：如果关键需求无法通过局部隔离、配置或有界改造满足，保留本 ADR 作为研究依据，并将可复用范围缩至经验证的独立模块。

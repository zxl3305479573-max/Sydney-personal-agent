# ADR-0002：TypeScript、PC 优先与可插拔云电脑

- 状态：方向已接受；首个 Provider 和部署细节待 M0 确定
- 日期：2026-11-03
- 关联需求：PA-011 至 PA-018
- 替代记录：[ADR-0001](0001-local-first-modular-monolith.md)

## 背景

用户在初始规划之后明确提出内置云电脑，Agent 可操作该电脑中的内容；同时要求参考 Grokbot 的前端功能组织，Agent 使用 TypeScript，先做 PC，并希望云电脑可插拔。

早期本地优先方案不足以完整表达独立桌面执行环境，需要调整，同时保留控制服务模块化单体的实现方式。

## 已确定方向

- Agent 使用 TypeScript，优先 PC 端。
- 内置真实桌面入口和电脑操控能力。
- Agent 在专属云电脑内可使用授权的桌面、文件、终端、安装及管理员能力。
- 云电脑通过统一接口接入，控制面与客体系统隔离。
- 前端参考 Grok Bot 的功能组织；具体项目解释和视觉细节仍有工作假设。

## 候选方案

| 方案 | 取舍 |
| --- | --- |
| 在 Agent 中直接使用一家桌面 SDK | 初期代码少，后续替换影响编排和界面 |
| 统一 ComputerService，加 Provider、Driver 和 Viewer 契约 | 增加少量边界设计，允许分步替换和测试 |
| 第一版建设完整动态插件平台 | 扩展灵活，但超出当前验证一个真实任务的需要 |

## 设计提议

采用统一服务和适配器边界。首个 Provider 建议接入自有专属 VM，第二个真实 Provider 再按需求从托管桌面服务选择。

生命周期管理与客体操控分别建模，不要求每个 Provider 都能创建、快照或停止实例。不支持的能力显式返回，不模拟成功。

PC 首版暂按浏览器工作台设计，是否提供原生安装包另行确定，不把该假设视为用户已确认。

## 影响与限制

- 新增桌面流、输入控制、客体驱动、持久性和资源费用的设计工作。
- 初版只实现一个真实适配器与测试替身，不同时集成所有候选。
- 断开连接不等于释放资源或停止计费。
- 切换 Provider 不保证系统镜像、进程或登录态迁移。
- 云电脑内的完整权限不包含控制服务器和云账号管理权限。

## 验证与重新评估

M0 确认首个场景、Provider、客体系统、预算、PC 交付形式和数据保留方式。首个真实 Provider 与测试替身通过统一契约验证后，再依据实际需要安排第二个 Provider。

若未来需要多用户、多台电脑并行、远程原生客户端或跨供应商镜像迁移，新增决策记录并明确成本与边界。

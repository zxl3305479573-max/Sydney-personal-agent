# ADR-0008：后台与云电脑分机部署

- 状态：部署方向已确定；跨机连接方案待实现和验收
- 日期：2026-11-04
- 关联需求：PA-004、PA-005、PA-006、PA-009 至 PA-018
- 替代：[ADR-0004](0004-native-server-and-task-orchestration.md) 的同机部署方向；保留其中的 Rakazo/Pi 和任务编排决策

## 决策

首版将控制面和执行面部署到两台 Linux 服务器。后台服务器运行 Web、API、Worker、Pi 及 PostgreSQL；独立云电脑运行图形桌面、浏览器和电脑驱动。优先复用现有 `SandboxProvider`、Run、授权和租约，不新建平行调度器；不以 Docker 为前提。

Agent 默认以云电脑上的受限桌面账号操作，不自动获得后台密钥、数据库、控制服务器、云账号管理或任一服务器的 root/sudo 权限。服务器分离不自动阻止桌面通过网络访问后台，必须验证网络、账号和服务认证边界。

## 通信方案

第一候选为后台向云电脑建立受限 SSH Unix socket 转发：后台现有 Provider 连接本地 socket，经加密隧道到云电脑上的驱动 socket。SSH 主机密钥固定，使用专用身份，云电脑上的转发账号仅获访问目标 socket 所需权限。驱动看到的是云电脑上发起 socket 连接的转发进程 UID，不是后台进程的 UID；必须明确该 UID、socket 文件权限和 `SO_PEERCRED` 配置并在实机验证。转发权限和端点的限制需实际核验，不能只依赖配置意图。

该方式是候选，当前尚无已验收的双机适配和部署配置。不得将驱动无认证暴露到公网；不得假设 SSH 连接本身替代 Run 授权、租约、审批或停止证据。双机时钟、短期租约、驱动重启后的 generation/fence、连接丢失、重连和 in-flight 操作结果均须验证；连接失败或副作用不明时不自动重放。

## 实施与验收

按 [双机实施方案](../../docx/design/TWO_HOST_DEPLOYMENT.md) 推进：先核对两台机器及现有服务，再实现连接管理和运行权限，最后在真实环境执行隔离、故障与首个任务验收。2 核 2 GiB 后台仅作为待测起点，不保证容纳全部服务及构建负载。桌面实时流和人工接管仍未实现；暂停/取消仍不能被当作已确认静止。

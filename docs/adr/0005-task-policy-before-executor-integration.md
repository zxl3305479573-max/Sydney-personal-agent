# ADR-0005：先实现纯派工与授权策略

- 状态：已采用；实际执行接线与持久化待实现
- 日期：2026-11-03
- 关联需求：PA-001、PA-003、PA-004、PA-005、PA-006、PA-010
- 前序决策：[ADR-0004](0004-native-server-and-task-orchestration.md)

## 背景

底座已有 Task、Run、Attempt、Ticket、审批、ExternalEffect 和租约。复制另一套 Ticket 或自行在内存调度，会增加状态冲突和重放风险。本机仅允许受控轻量验证，尚无授权服务器和生产模型。

## 决策

在原应用的 `packages/core` 增加无 I/O 的派工和授权策略，使用显式输入、固定时钟及确定性离线测试。策略只返回意图或拒绝原因，不创建运行实例，不签发授权，也不代替数据库事务、操作系统权限或已有审批。

派工策略使用现有 Run 状态机。相同客户端 nonce 返回原 Run 引用，包含失败或终止记录；此处的“复用”仅指幂等响应，不能再次调度该 Run。新 nonce 仅在无活动 Run、无未知副作用、历史完整和次数有界时产生创建意图；失败重试必须显式请求，保留原 Run 与 Attempt。取消和完成的任务不能通过新请求重开。

授权策略绑定用户、空间、Bot、任务和 Run，按同一条目的工具、动作、资源精确匹配，限制签发时间、有效期和撤销状态。来源必须由可信服务加载，不能由模型声明。现有审批必须允许；新范围授权不覆盖已有拒绝。路径规范化、链接解析、网络地址检查、身份验证和持久化撤销不在纯函数中实现。

实际接入时，将读取历史、判定、创建 Run/幂等键和写入审计放进现有事务与资源锁边界；执行前再检查最新授权、取消、电脑接管和租约 fence。没有完成这些步骤前，新模块不会保护现有工具调用。

## 影响

- 不增加依赖、模型调用、数据库、队列或新的 Provider 类型。
- 不改底座生产 host 命令保护，不放开桌面或终端权限。
- 策略中的 `maxRuns` 只限制新建 Run 的数量，不限制一个 Run 内的 Attempt、模型重试或 token 消耗；后续预算分别实现。
- 全部历史必须由可信存储给出一致快照，`historyComplete` 和未核对副作用标志不能接受客户端自报。
- 生产首次部署、升级回滚和端到端行为仍在 P3 至 P6 验收。

详细映射见 [任务设计](../../docx/design/TASK_RUN_MAPPING.md)，工程场景见 [任务书](../../docx/design/FIRST_TASK.md)。

## 后续落实：状态投影与只读存储适配

2026-11-03，沿用上述决策新增任务投影与现有数据库历史读取，不增加表或调度器。查询要求匹配的既有 tenant 上下文，在一个 RepeatableRead 事务中有界读取元数据；截断即标记不完整。取消请求与静止确认分别展示，Run completed 仍要求独立完成证据。实现与局限见 [状态投影设计](../../docx/design/TASK_PROJECTION.md)；真实 PostgreSQL 隔离与 RLS 尚未验收，不把替身测试当作生产证明。

# ADR-0015：PC 后台部署到云电脑

状态：规划中

日期：2026-11-05

## 背景

用户确认后期 PC 端配套后台也运行在云电脑。当前双机方案把 Web/API、Worker、Pi、PostgreSQL 和模型连接放在后台服务器，把桌面、浏览器和驱动放在云电脑；Web 已经迁到云电脑试运行，但 PC 客户端仍按连接后台 Web 页面规划。

如果直接把全部后台迁到云电脑，会同时移动数据库、任务控制、模型凭据和审计边界，增加数据丢失、权限扩张和云电脑重启影响。因此需要明确“PC 后台”和“主后台控制服务”不是同一个组件。

## 决策

后期采用三层目标结构：

```text
PC Electron 客户端
        │
        ▼
云电脑 PC 后台
（渲染产物、PC 专用 BFF、WebSocket/屏幕代理）
        │ 受控双机连接
        ▼
主后台控制服务
（API、Worker、Pi、PostgreSQL、模型凭据、任务与审计）
        │
        ▼
云电脑桌面与原生驱动
```

- 云电脑 PC 后台负责 PC 客户端需要的渲染产物、协议适配、屏幕代理和必要的轻量 BFF。
- 主后台继续保存用户认证主数据、任务状态、Run/Attempt、授权、审计、模型凭据、数据库和 Worker。
- PC 后台通过受控 HTTPS、Unix socket 或现有 SSH 隧道访问主后台；具体协议和端口在实现阶段确定。
- 正式入口主机名由 `PC_BACKEND_HOSTNAME` 提供，云电脑 Web/PC 后台只把该主机名加入 Host 白名单；TLS 终止、证书和公开 DNS 由部署侧反向代理负责。
- 云电脑 PC 后台不保存主后台 root 密钥、数据库密码、模型明文密钥或云电脑维护私钥。
- 云电脑桌面账号不能直接访问 PC 后台配置、主后台数据库或控制面管理接口。
- PC 客户端不直接访问驱动 socket、数据库或管理端口；所有请求经过认证的 PC 后台和主后台权限检查。

## 影响

优点：

- 将 Web 渲染、PC 专用代理和屏幕转发继续放在云电脑，减少主后台 Web 进程的内存压力。
- PC 后台与桌面和屏幕通道同机，减少屏幕代理的跨机路径。
- 主后台保留控制数据和凭据，云电脑重启不会直接丢失任务与账户数据。

代价与风险：

- 增加 PC 客户端到主后台之间的一跳，需要处理认证转发、超时、重连和结果未知。
- 云电脑同时运行桌面、浏览器、驱动、Web 和 PC 后台，必须设置内存、CPU、文件描述符和进程重启限制。
- 云电脑重启期间 PC 客户端不可用，但主后台任务状态必须保持可核对；不能把连接断开当成任务停止。
- PC 后台如果拥有过宽的主后台访问权限，可能成为绕过授权的入口；接口和服务账号必须最小化。

## 验收条件

1. PC 客户端只能通过认证的 PC 后台访问应用，不可直接访问驱动、数据库和管理端口。
2. PC 后台只能调用主后台允许的 API，不能使用 root SSH、数据库超级用户或模型明文凭据。
3. 云电脑 PC 后台重启、主后台重启、隧道断开和恢复均能显示明确状态；未确认的外部动作保持未知。
4. 云电脑资源压力在桌面、浏览器、屏幕代理和 PC 后台同时运行时可测量，不能只用空闲内存判断容量。
5. 停止 PC 后台或回滚到旧 Web 入口时，主后台数据库、任务和用户会话不被删除。

本 ADR 只确定部署边界，不代表 PC 后台已经实现或已在服务器部署。

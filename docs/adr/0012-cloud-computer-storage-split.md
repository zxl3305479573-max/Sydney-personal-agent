# ADR-0012：云电脑执行存储与后台控制存储分层

- 状态：存储迁移暂缓；Web 进程已迁移试运行
- 日期：2026-11-04
- 关联需求：PA-004、PA-009、PA-010、PA-012、PA-015、PA-017、PA-018
- 相关文档：[双机实施方案](../../docx/design/TWO_HOST_DEPLOYMENT.md)、[存储划分与迁移方案](../../docx/design/STORAGE_SPLIT_MIGRATION.md)

## 背景

实际拓扑是一台后台服务器和一台云电脑。盘点时后台可用内存约 65 MiB，API、Worker 和 Web 服务分别占约 542、361 和 139 MiB；后台数据目录仅约 452 KiB。搬迁这些文件无法实质降低进程内存，因此暂不部署对象存储，优先调查进程减压。

仓库已经提供 S3 兼容对象存储、Agent home 迁移和本地 artifact 迁移能力。本次不新增数据库、不把 PostgreSQL 放到云电脑，也不让桌面账号接触后台凭据。

## 决策

### 后台服务器保留

- API、Worker、Pi Runtime 和任务队列；Web 的迁移现状见 ADR-0013。
- PostgreSQL 中的 Task、Run、Attempt、授权、租约、审计和文件元数据。
- 内容加密密钥、模型密钥、OAuth 凭据、隧道密钥和服务配置。
- 只读运行缓存、短期 staging、健康检查和受限日志。

### 云电脑保留

- 当前任务的工作区文件。
- 浏览器下载、导入文件和任务产生的中间文件。
- 桌面账号的浏览器配置、登录态和 Agent home。
- 图片、PDF、压缩包等需要在桌面侧处理的临时产物。

### 后续候选：云电脑侧持久化存储

日后数据量增长时，可评估云电脑上的私有 S3 兼容服务或其他私有端点；当前未部署或配置。后台上传的文件内容按现有实现加密，密钥留在后台。

对象存储保存：

- Agent home 的加密修订。
- 附件和生成 artifact 的加密内容。
- 其他明确纳入迁移清单的可恢复文件。

对象存储不保存：

- PostgreSQL 数据库文件。
- 模型、OAuth、SSH 或数据库凭据。
- 未经授权的完整运行日志和 Pi 原始会话记录。

## 关键边界

1. 数据库仍是文件元数据、权限和任务状态的唯一来源；候选对象存储只保存内容。
2. 云电脑桌面账号不获得对象存储凭据，也不直接访问对象 URL。
3. 后台通过 Provider 把活动文件送入云电脑工作区；不把后台目录挂载到桌面。
4. Artifact 迁移必须先上传、回读校验，再更新 PostgreSQL 的 `storageKey`。
5. Agent home 迁移保留本地副本，完成抽样恢复和重启验证后才能清理。
6. `PI_SESSION_RECORDING` 默认关闭；未完成加密和保留策略前，不把原始 Pi 会话迁到云电脑。
7. 云电脑掉线、对象存储不可达或文件副作用未知时，不自动重放任务动作。

## 迁移顺序

1. 盘点两台服务器的内存、磁盘、数据目录、服务和当前任务。
2. 在云电脑侧准备私有对象存储端点、独立 bucket/prefix、访问策略和备份策略。
3. 在后台配置 `OBJECT_STORAGE_*`，先执行 `home-storage migrate --dry-run` 和 `shared-storage artifacts --dry-run`。
4. 停止所有 API/Worker 副本后迁移 Agent home 和 artifact；旧本地文件暂不删除。
5. 重启 API/Worker，验证任务元数据、附件读取、云电脑工作区、浏览器配置和对象存储恢复。
6. 测量后台 RSS、交换空间、CPU、磁盘增长和云电脑磁盘增长。
7. 仅在抽样恢复和回滚窗口通过后删除后台大文件副本。

## 未完成事项

- 两台机器已盘点；后台 Web 后续迁往云电脑试运行，见 [ADR-0013](0013-isolated-cloud-web-proposal.md)。
- 云电脑对象存储端点、bucket、磁盘路径和备份尚未配置，也没有执行迁移命令。
- 现有原生 Provider 的跨机文件流和完整恢复仍需真实服务器验证。
- 迁移完成前，后台本地 artifact 和 home 文件继续保留，不能宣称后台已经释放对应空间。

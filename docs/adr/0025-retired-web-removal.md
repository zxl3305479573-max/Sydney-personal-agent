# ADR-0025：删除退役 Web 服务并保留客户端共用界面

- 状态：已接受
- 日期：2026-11-20
- 关联需求：PA-023

## 背景与决定

用户明确允许网页退役后直接删除。此前生产已切换为客户端直连，旧 `web` 与 `native-screen-web-loopback` 容器均已停止。删除这两个专属容器，源码生产 Compose 移除独立 Web 服务、旧资源归档挂载和 Caddy 对 Web 的依赖；生产网关默认将认证回调与屏幕路由交给 API，其他浏览器应用路径返回 404。生产更新器不再请求重建 Web。

`apps/web` 同时是 Windows 安装包的 React／Vite 界面来源，桌面 `extraResources` 从 `../web/dist` 打包到 `resources/web`。该源码与包内界面继续保留，认证、Slack／MCP 回调、原生无影／noVNC 资源及画面桥不随旧网页服务删除。开发预览与既有本地镜像拓扑仍可复用同一界面，不计为生产网页重新上线。

Sydney 的默认镜像目标为 `server`，仅复制及安装后台工作区所需内容，编译 API／Worker 并按生产配置准备 API 无影资源。保留可选本机电脑 supervisor 及其镜像构建上下文。Rakazo 上游预构建自托管镜像使用 `self-host` 目标，载入完整工作区再构建 Web。生产更新名单默认 API／Worker，忽略旧 Web 及其专用桥，现用 API 桥可随生产覆盖显式更新。生产部署以当前版和回退版均为直连拓扑为前提。

原生 Linux 覆盖示例使用共享 API 网络命名空间的 `native-screen-api-loopback`，并将它加入可选 updater 的更新及回退名单。IP 代理隔离演练使用合成 API 上游检查当前默认路由，沿用域名和 IP 的认证回跳、画面及日志脱敏验证，并检查旧入口 404。

Windows 安装版使用内置渲染器直连。旧 `mode: "new"` 启动时进入选服，经成功保存后才更新 profile；移除安装包内本地栈资源和可用的启动入口。macOS、Linux 安装版及未打包开发模式沿用各自本地栈入口。

## 验收与运维影响

取消以恢复旧 Web、旧 Web 画面桥和再次切流为前提的完整演练；客户端登录、授权回跳、画面、升级及直连版本回退纳入 [个人生产首版测评](../../docx/ACCEPTANCE.md#个人生产首版测评)。

仅删除经项目／服务标签和退出状态核对的旧容器，不使用强制删除或卷删除。共用应用镜像、数据库、工作区、用户数据、旧资源卷和备份均未删除。源码配置清理与生产持久配置的发布分别记录，不能用源码改动声称服务器配置已更新。生产旧配置仍含受停用 profile 限制的历史定义时，不再主动启用 `legacy-web`。

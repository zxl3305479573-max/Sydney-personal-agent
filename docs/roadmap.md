# 开发路线图

状态：阶段规划，无日期承诺。按完成门槛推进，不以文档中的阶段名称作为功能已实现的证明。

后续开发执行与阶段状态统一维护在 [docx/PLAN.md](../docx/PLAN.md)。下述 M0 至 M4 保留产品里程碑背景；其中 Docker 试点先行的顺序由 [ADR-0004](adr/0004-native-server-and-task-orchestration.md) 替代，不要求为完成前置阶段而恢复本机 Docker。

## M0：确定场景与技术基线

交付内容：

- 补齐首个场景任务书，确定代表性输入、预期输出和授权范围。
- 确定第一版需求范围及非功能指标。
- 在 TypeScript、PC 优先的前提下确定交付形式、框架、模型、存储和测试工具。
- 选择首个云电脑 Provider、客体操作系统、持久性和管理员权限范围。
- 完成架构决策记录，明确控制侧数据路径、模型发送边界、保留策略及云资源预算。

完成门槛：任务书可直接用于验收；选型有依据；未决定事项不再阻碍初始化。

当前状态：TypeScript、PC 优先、内置可插拔云电脑及 Grok Bot 功能参考已确定；已决定按 [ADR-0003](adr/0003-rakazo-fork-as-execution-base.md) 在独立目录评估 Rakazo Fork。首个真实任务及底座适配边界仍待试点确认。

底座源码导入、静态检查和 Pi 离线测试已完成。按用户要求停止本机 Docker 运行试点，后续运行验证转到 Linux 服务器；服务器与真实模型尚未配置，不标记 M1 完成。

## M1：建立可运行骨架

依赖：M0 完成及 ADR-0003 的底座试点通过。

交付内容：

- 建立应用入口、模块目录、依赖锁定和配置校验。
- 提供配置示例，隔离真实密钥和运行数据。
- 建立模型、工具、存储接口及最小实现。
- 建立 ComputerService、Provider、Driver 和 DesktopViewer 契约，提供可控的测试替身。
- 加入格式检查、静态检查和现有测试的自动化入口。

完成门槛：干净环境能够按 README 启动；缺失配置时提示明确；基础检查通过。

对应需求：PA-009、PA-010、PA-017。

## M2：跑通一个真实任务

依赖：M1 完成。

交付内容：

- 实现手动提交、排队、执行、结果展示和记录查询。
- 接入一个真实模型和首个场景所需的最少工具。
- 实现执行步数、调用超时和总时限控制。
- 完成工具参数校验、资源边界和必要的授权确认。
- 接入一个真实云电脑 Provider，在 PC 工作台内显示桌面并完成截图、输入、文件和终端操作。
- 实现电脑状态、接入、断开和重连，按能力声明展示可用生命周期操作。

完成门槛：代表性输入能完成真实操作；结果可核对；未授权请求无法执行。

对应需求：PA-001、PA-002、PA-003、PA-004、PA-011、PA-012、PA-013、PA-018。

## M3：验证失败与恢复

依赖：M2 完成。

交付内容：

- 处理模型失败、工具失败、取消、授权拒绝及过期。
- 持久化任务和步骤，识别进程中断。
- 区分操作失败与操作结果未知，限制有副作用调用的重试。
- 验证脱敏、路径边界和执行记录。
- 验证人工接管、外部急停、控制面隔离、会话代次和电脑过期。
- 按首个 Provider 能力验证持久化、备份恢复及可选的快照，不承诺跨供应商无损迁移。

完成门槛：失败用例有明确结果；重启可查到历史；取消后不再安排后续步骤；不重复执行结果未知的操作。

对应需求：PA-005、PA-006、PA-010、PA-014、PA-015、PA-016、PA-017，并复验 PA-003、PA-004。

## M4：加入记忆并交付第一版

依赖：M3 完成。

交付内容：

- 实现显式记忆的保存、查看、修改、删除和必要检索。
- 支持按编号或关键词查找历史任务。
- 补齐安装、使用、故障处理、数据清理和备份恢复说明。
- 对照第一版需求进行验收，记录限制和后续工作。
- 说明云电脑资源、停机费用、文件保留方式和连接撤销流程。

完成门槛：已冻结的 P0、P1 需求全部通过验收；能够在新环境复现；没有未处理的阻断性权限或数据问题。

对应需求：PA-007、PA-008，以及全部第一版需求的回归验收。

## 第一版之后

视实际使用反馈再考虑定时任务、更多工具、跨设备、多模型切换和更复杂的记忆检索。每项扩展先给出使用场景与验收条件，再进入排期。

## 进度记录规则

- 状态统一使用：未开始、进行中、已完成、阻塞。
- “已完成”必须附实际产物和验证证据；纯规划不能标为功能完成。
- 阻塞项写明缺少的信息或依赖，不用预计日期代替解决条件。
- 范围变化同步更新需求、架构决策和受影响阶段。

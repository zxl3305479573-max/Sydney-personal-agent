# PostgreSQL 18 合成 ACL 演练候选

状态：2026-11-11 已完成针对性静态复审，执行者报告在授权维护机完成一次
合成演练；详情和限制见 `docx/VALIDATION.md`。实施范围仅为授权的
`sydney-backend-admin` 维护机上的全新无网络容器与合成数据，禁止用于生产。

## 候选设计

以 `pg16-acl-synthetic-drill.sh` 为基线移植其脚本可信路径、封存快照、
Docker 守护进程与套接字身份检查，以及容器随机身份、清理复核和失败退出
机制；不得把名称或环境变量当作身份凭证。原脚本及执行环境仍需可信，
系统管理员和 Docker 守护进程属于信任边界。`sydney-backend-admin` 是本机
SSH 别名；脚本检查实际主机名 `iZbp1fb03iz01hcvusndc1Z`、UTS 命名空间、
本机 machine-id 与预先部署的主机身份摘要，并在每次 daemon 检查时复核；
这依赖可信管理员、可信本机身份文件和正确的独立预置，不是远程证明。

运行前须由授权维护人员通过可信渠道确认 SSH 别名所指维护机的
machine-id 及其对应关系，并预先在该机以 root 部署
`/etc/sydney-pg18-drill-host-id.sha256`：内容为去除首尾空白后的小写
32 位 machine-id ASCII 文本的 SHA-256 小写十六进制摘要及可选换行。此文件
及 `/etc/machine-id` 必须是 root 所有、单硬链接、无符号链接、组和其他用户
不可写的普通文件，`/` 和 `/etc` 也须由 root 拥有且不可由组或其他用户写入。
脚本不创建或自动注册该文件；缺失或不匹配时拒绝。本次演练以已配置严格
known_hosts 校验的 SSH 连接为信任锚，在同一连接读取 machine-id 并临时
部署 pin；不声称经独立物理渠道认证。pin 不是硬件证明，可信管理员、
主机凭据和身份文件遭篡改或复制均不在其防护能力内。

- 脚本固定使用本机缓存镜像
  `sha256:edb0c08dc33befd0262ab3b5cf1c4f3f8cfd8b09e88c05b45adee29d6761ddb6`，
  禁止拉取。创建前检查镜像 ID、声明的卷及 `PGDATA`，与预期不符时拒绝。
- 镜像声明卷为 `/var/lib/postgresql`，`PGDATA` 为
  `/var/lib/postgresql/18/docker`。使用 `--mount type=tmpfs` 将受限 tmpfs
  挂载在卷声明的父路径 `/var/lib/postgresql`，而非只挂载其下的 `PGDATA`。
  同时为 `/run/postgresql` 和 `/tmp` 配置有界 tmpfs，以只读根文件系统、
  `none` 日志驱动运行。检查 Docker 配置和实际挂载列表；执行数据库操作前后
  检查容器内 mountinfo 的根目录只读、三个 tmpfs 及其下没有嵌套挂载。这些
  检查依赖 Docker 返回的配置与挂载列表，不能证明 Docker 未创建不可见或
  已脱离容器的匿名卷；匿名卷是否避免仍须独立复审和针对性验证。
- 源和目标分别创建带随机标识的新容器，使用 `--network none`、固定镜像、
  资源限制及容器内 Unix socket；绝不接受既有容器、数据库、数据目录或卷。
  启动前后检查容器身份和隔离配置，在数据库操作前后复核容器身份、挂载，
  并检查 `/proc/net/dev` 仅有 loopback；数据库连接只使用固定 Unix socket
  和清洁环境。检查仅是这些时点的快照，不排除两次检查之间的变化、
  特权进程干预，或 Docker 与内核本身不可信；loopback 和 Unix socket 仍存在。
  仅检查接口列表与 Docker 网络配置，不构成对所有通信路径的独立证明。
- 只创建合成角色、成员关系、对象、授权和数据。全局角色先于包含 owner、
  ACL 的数据库归档恢复，过滤已存在引导管理员的 `CREATE ROLE`；恢复对 SQL
  和归档错误退出。对照 `--no-privileges` 归档，验证实际读取在 schema 和表
  两层分别被拒绝。
- 创建前输出随机 nonce 和两个预定容器名；发出创建请求后，只有返回合法容器
  ID 且配置检查通过才解除创建结果未知状态。创建失败、中断、返回异常或
  随后检查失败时均以非零退出，打印可能迟到的容器或匿名卷残留，并保留
  该名称供后续排查；一次查询未发现容器不能证明 daemon 不会迟到创建资源。
  `SIGKILL` 或主机故障可能阻止陷阱运行，应使用此前输出的身份排查。
- 清理时仅删除身份匹配且没有非 tmpfs 挂载的已确认容器，并复查容器不存在。
  如果发现非 tmpfs 挂载，则保留容器供人工检查，不自动删除卷。脚本不做
  全局卷枚举，也不能证明 Docker 创建失败时没有遗留匿名卷；须由审查者
  评估该缺口及维护机演练的验证方案。身份不符、守护进程故障或清理结果
  未知时报告失败；未知创建结果的容器不会被自动清理。容器移除或移除后
  查询失败、超时均报告结果未知，保留容器名、完整 ID 和 nonce 供排查，
  不能据此断定容器仍存在或已删除。
  只读根、tmpfs 和
  禁用容器日志降低合成数据持久化风险，但不证明完全不落盘：swap、内核、
  daemon、调用方输出、宿主机审计及特权观察者仍在控制范围外。

每次 Docker CLI 调用通过系统 `timeout` 设置 30 秒期限，超时后先发 TERM，
5 秒后发 KILL；前后 daemon 守卫各设 10 秒期限和 2 秒强制终止宽限期。
非零或超时均不代表 daemon 已取消请求，尤其不能证明创建、删除或容器内
命令没有稍后执行；脚本将创建和清理相关的不确定结果报告为未知。此限制
不是整个脚本的总时限，初始守卫、内核不可中断睡眠和系统级故障也可能超出
这些时间；超时处理及进程清理尚未实际验证。

## 审查与验收门槛

需要独立审查完整脚本及最终摘要，重点检查镜像卷与 tmpfs 的 Docker 行为、
创建失败时的残留、主机身份 pin 的部署与信任、只读根和 tmpfs 兼容性、
身份校验与清理竞态、超时和迟到请求、管道及标准输入、错误传播、PG18
恢复行为。审查通过后，才能在指定维护机使用受控环境执行并核对容器、挂载
和清理结果；任何实际 Docker 演练均须由主窗口安排。本文件不记录未执行的
验证结果，也不授权生产数据库采集。

计划使用的启动方式（尚未验证）：

```bash
/usr/bin/env -i PATH=/usr/sbin:/usr/bin:/sbin:/bin LC_ALL=C \
  /bin/bash -p infra/compose/pg18-acl-synthetic-drill.sh
```

执行需要 root、可信的本机 Docker 守护进程及系统工具；脚本和所有祖先目录
须满足脚本内的 root 所有权、不可由组或其他用户写入、无符号链接等检查。
初始脚本和 Bash 在检查前已执行，必须事先可信；脚本启动后封存的快照不能
弥补不可信的初始入口。

演练使用 `--no-role-passwords` 并过滤引导角色创建语句；即使通过，也不能
证明密码哈希、加密备份、不同引导管理员、真实数据或跨源一致性得到恢复。
